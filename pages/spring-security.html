🔐 Spring Security

Spring Security — фреймворк для аутентификации и авторизации. На джуна спросят: что такое JWT, как защитить эндпоинты, базовая конфигурация.

Аутентификация vs Авторизация

АутентификацияАвторизация
ВопросКто ты?Что тебе можно?
ПримерЛогин + пароль, JWT-токенРоли: ADMIN может удалять, USER — нет
АннотацииAuthenticationManager@PreAuthorize, @RolesAllowed
Аутентификация — проверка "кто ты?" (логин/пароль, токен, OAuth2). Авторизация — проверка "что тебе можно?" (роли, права доступа к URL/методам). В Spring Security: AuthenticationManager для аутентификации, @PreAuthorize и SecurityFilterChain для авторизации.

Базовая конфигурация (Spring Boot 3.x)

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable()) // для REST API — отключаем CSRF
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/public/**").permitAll()     // всем
                .requestMatchers("/api/admin/**").hasRole("ADMIN") // только админам
                .requestMatchers("/api/user/**").hasAnyRole("USER", "ADMIN")
                .anyRequest().authenticated()                      // остальное — после логина
            )
            .sessionManagement(session ->
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS) // без сессий, для JWT
            )
            .httpBasic(Customizer.withDefaults()); // или formLogin или JWT-фильтр

        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(); // хеширование паролей
    }
}

JWT (JSON Web Token) — основа современных API

JWT — компактный токен, который передаётся в заголовке Authorization. Сервер не хранит сессии (stateless).

Структура JWT:

Header.Payload.Signature

Header:   {"alg": "HS256", "typ": "JWT"}
Payload:  {"sub": "123", "name": "Иван", "role": "USER", "exp": 1718000000}
Signature: HMAC-SHA256(base64(header) + "." + base64(payload), secret_key)

Как работает JWT:

1. Клиент: POST /api/auth/login (логин + пароль)
2. Сервер: проверяет, создаёт JWT, возвращает в ответе
3. Клиент: сохраняет JWT (localStorage/cookie)
4. Клиент: каждый следующий запрос — добавляет заголовок:
   Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

5. Сервер: проверяет подпись → извлекает пользователя → пропускает запрос

Генерация JWT (упрощённо):

// Зависимость: io.jsonwebtoken:jjwt-api:0.12.5
@Service
public class JwtService {

    @Value("${jwt.secret}")
    private String secret; // минимум 256 бит

    public String generateToken(UserDetails user) {
        return Jwts.builder()
            .subject(user.getUsername())
            .claim("role", user.getAuthorities().toString())
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + 86400000)) // 24 часа
            .signWith(Keys.hmacShaKeyFor(secret.getBytes()))
            .compact();
    }

    public String extractUsername(String token) {
        return Jwts.parser()
            .verifyWith(Keys.hmacShaKeyFor(secret.getBytes()))
            .build()
            .parseSignedClaims(token)
            .getPayload()
            .getSubject();
    }

    public boolean isTokenValid(String token) {
        try {
            extractUsername(token);
            return true;
        } catch (JwtException e) {
            return false;
        }
    }
}

JWT-фильтр:

@Component
public class JwtFilter extends OncePerRequestFilter {

    @Autowired
    private JwtService jwtService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                     HttpServletResponse response,
                                     FilterChain chain)
            throws ServletException, IOException {
        String header = request.getHeader("Authorization");

        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            if (jwtService.isTokenValid(token)) {
                String username = jwtService.extractUsername(token);
                // Устанавливаем пользователя в SecurityContext
                SecurityContextHolder.getContext().setAuthentication(
                    new UsernamePasswordAuthenticationToken(username, null, List.of())
                );
            }
        }
        chain.doFilter(request, response);
    }
}

Аннотации для авторизации

АннотацияПример
@PreAuthorize @PreAuthorize("hasRole('ADMIN')")
@PostAuthorize @PostAuthorize("returnObject.userId == authentication.principal.id")
@Secured @Secured("ROLE_ADMIN")
@RolesAllowed @RolesAllowed("USER") 
@RestController
@RequestMapping("/api/users")
public class UserController {

    @GetMapping
    @PreAuthorize("hasRole('ADMIN')") // только админ
    public List<User> getAll() { ... }

    @GetMapping("/{id}")
    @PreAuthorize("#id == authentication.principal.id") // только свои данные
    public User getById(@PathVariable Long id) { ... }
}

Хеширование паролей (BCrypt)

// НИКОГДА не храните пароли в открытом виде!

@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}

// Регистрация
public User register(String username, String rawPassword) {
    String hashedPassword = passwordEncoder.encode(rawPassword);
    // храним в БД: $2a$10$N9qo8uLOickgx2ZMRZoMye...
    return userRepo.save(new User(username, hashedPassword));
}

// Проверка пароля
public boolean checkPassword(String rawPassword, String hashedPassword) {
    return passwordEncoder.matches(rawPassword, hashedPassword);
}

Полный поток: регистрация + логин + доступ

// 1. Регистрация
POST /api/auth/register
{
    "username": "ivan",
    "password": "secret123"
}
→ 201 Created

// 2. Логин
POST /api/auth/login
{
    "username": "ivan",
    "password": "secret123"
}
→ 200 OK + { "token": "eyJhbGciOiJIUzI1NiIs..." }

// 3. Запрос с токеном
GET /api/users
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
→ 200 OK (если роль ADMIN) или 403 Forbidden (если USER)
