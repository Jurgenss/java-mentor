🍃 Spring Core — IoC, DI, бины

Spring — самый популярный фреймворк в Java. На собесе на джуна спросят: что такое IoC/DI, что такое бин, scope бинов, @Component vs @Bean.

IoC (Inversion of Control) — инверсия управления

Суть: не ты управляешь созданием объектов, а фреймворк.

// Без IoC — ты сам создаёшь зависимости
public class UserService {
    private UserRepository repo = new UserRepository(); // жёсткая связь
}

// С IoC (Spring) — контейнер создаёт и внедряет
@Service
public class UserService {
    @Autowired
    private UserRepository repo; // Spring сам подставит
}

Раньше ты управлял кодом. Теперь код управляется Spring-контейнером — отсюда "инверсия управления".

DI (Dependency Injection) — внедрение зависимостей

DI — это реализация IoC. Зависимости не создаются внутри класса, а "впрыскиваются" извне.

Три способа внедрения:

СпособАннотацияРекомендация
Через конструктор @Autowired на конструкторе (можно опустить, если конструктор один) ✅ Лучший способ. Неизменяемость, удобно тестировать.
Через сеттер @Autowired на сеттере Для опциональных зависимостей.
Через поле @Autowired на поле ❌ Не рекомендуется. Сложно тестировать, скрытые зависимости. 
// ✅ Конструктор (рекомендуемый)
@Service
public class UserService {
    private final UserRepository repo;

    public UserService(UserRepository repo) { // @Autowired можно не писать
        this.repo = repo;
    }
}

// С Lombok — ещё короче:
@Service
@RequiredArgsConstructor
public class UserService {
    private final UserRepository repo;
}

// ❌ Поле (не рекомендуется)
@Service
public class UserService {
    @Autowired
    private UserRepository repo; // нельзя сделать final, сложно тестировать
}
IoC — принцип: фреймворк управляет объектами, а не разработчик. DI — реализация IoC: зависимости внедряются извне. Лучший способ DI — через конструктор: объект сразу создаётся в готовом состоянии, зависимости неизменяемы (final), легко тестировать.

Bean (бин)

Bean — это объект, которым управляет Spring-контейнер. Создаётся, настраивается и уничтожается контейнером.

Способы объявить бин:

СпособАннотацияГде использовать
Стереотипные аннотации @Component, @Service, @Repository, @Controller Свои классы
Java-конфигурация @Bean в @Configuration-классе Сторонние классы, ручная настройка
XML-конфигурация (устарело) <bean> в XML Легаси

@Component vs @Bean:

@Component@Bean
УровеньКлассМетод
Автоматическое сканирование✅ Да❌ Нет (явно объявляем)
КогдаСвои классыСторонние классы (RestTemplate, DataSource)
// @Component — на своём классе
@Component
public class EmailService { ... }

// @Bean — для стороннего класса
@Configuration
public class AppConfig {
    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate(); // RestTemplate — не наш класс
    }
}

Стереотипные аннотации

@Component       // общий бин
 ├── @Service     // бизнес-логика
 ├── @Repository  // работа с БД (транслирует SQL-исключения в Spring)
 └── @Controller  // веб-контроллер
      └── @RestController = @Controller + @ResponseBody (JSON API)

Все четыре создают бины. Разница — в семантике (читаемость) и доп. функциональности.

Scope бинов (область видимости)

ScopeОписание
singleton По умолчанию. Один экземпляр на весь контейнер. Все запросы получают тот же объект.
prototype Новый экземпляр при каждом запросе бина.
request Один экземпляр на HTTP-запрос (только в веб-приложениях).
session Один экземпляр на HTTP-сессию (веб).
application Один экземпляр на ServletContext (веб). 
@Component
@Scope("prototype") // или @Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE)
public class ReportGenerator { ... }

Нюанс: если singleton-бин зависит от prototype-бина — новый prototype не будет создаваться при каждом вызове. Решение: @Lookup или ObjectFactory.

Жизненный цикл бина

  1. Создание экземпляра (конструктор)
  2. Внедрение зависимостей (@Autowired)
  3. Пост-инициализация (@PostConstruct, InitializingBean)
  4. Бин готов к использованию
  5. Пред-уничтожение (@PreDestroy, DisposableBean)
  6. Уничтожение
@Component
public class MyBean {
    @PostConstruct
    public void init() {
        System.out.println("Бин создан и настроен!");
    }

    @PreDestroy
    public void destroy() {
        System.out.println("Бин уничтожается");
    }
}

Контекст Spring (ApplicationContext)

Контейнер, который хранит и управляет бинами. Создаётся при запуске приложения.

// В Spring Boot — автоматически через @SpringBootApplication
@SpringBootApplication
public class MyApp {
    public static void main(String[] args) {
        ApplicationContext ctx = SpringApplication.run(MyApp.class, args);
        MyService service = ctx.getBean(MyService.class); // получить бин
    }
}
