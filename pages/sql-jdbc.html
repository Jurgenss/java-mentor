🗄 SQL и JDBC

На собесе на джуна по SQL спросят JOIN, WHERE vs HAVING и основы JDBC. Разбираем всё по порядку.

SQL JOIN — соединение таблиц

Тип JOINЧто возвращаетВизуально
INNER JOIN Только строки с совпадениями в обеих таблицах Пересечение двух кругов
LEFT JOIN Все строки из левой таблицы + совпадения из правой (NULL если нет) Весь левый круг
RIGHT JOIN Все строки из правой + совпадения из левой Весь правый круг
FULL JOIN Все строки из обеих таблиц Оба круга целиком

Пример:

-- Таблицы
users:                       orders:
id | name                   id | user_id | amount
---+-------                 ---+---------+-------
1  | Иван                   1  | 1       | 100
2  | Мария                  2  | 1       | 200
3  | Пётр                   3  | 3       | 300

-- INNER JOIN — только те, у кого есть заказы
SELECT u.name, o.amount
FROM users u
INNER JOIN orders o ON u.id = o.user_id;
-- Иван | 100
-- Иван | 200
-- Пётр  | 300
-- (Марии нет — у неё нет заказов)

-- LEFT JOIN — все пользователи, даже без заказов
SELECT u.name, o.amount
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;
-- Иван  | 100
-- Иван  | 200
-- Мария | NULL
-- Пётр  | 300

WHERE vs HAVING

WHEREHAVING
Когда применяетсяДО группировки (GROUP BY)ПОСЛЕ группировки
Что фильтруетОтдельные строкиГруппы (агрегаты)
Агрегатные функции❌ Нельзя✅ Можно (SUM, AVG, COUNT...)
-- WHERE — до группировки
SELECT department, COUNT(*)
FROM employees
WHERE salary > 50000          -- фильтруем строки
GROUP BY department;

-- HAVING — после группировки
SELECT department, COUNT(*)
FROM employees
GROUP BY department
HAVING COUNT(*) > 5;           -- фильтруем группы

-- Можно вместе
SELECT department, AVG(salary) as avg_sal
FROM employees
WHERE hire_date > '2020-01-01'  -- сначала фильтр строк
GROUP BY department
HAVING AVG(salary) > 70000;     -- потом фильтр групп

JDBC — 5 шагов

  1. Загрузить драйвер (в современных версиях автоматически через ServiceLoader)
  2. Создать соединение: DriverManager.getConnection(url, user, password)
  3. Создать запрос: Statement / PreparedStatement
  4. Выполнить: executeQuery() (SELECT) или executeUpdate() (INSERT/UPDATE/DELETE)
  5. Закрыть ресурсы: try-with-resources

Полный пример:

String url = "jdbc:postgresql://localhost:5432/bank";
String user = "postgres";
String password = "secret";

try (Connection conn = DriverManager.getConnection(url, user, password);
     PreparedStatement stmt = conn.prepareStatement(
         "SELECT id, name, balance FROM accounts WHERE balance > ?"
     )) {

    stmt.setDouble(1, 1000.00);

    try (ResultSet rs = stmt.executeQuery()) {
        while (rs.next()) {
            int id = rs.getInt("id");
            String name = rs.getString("name");
            double balance = rs.getDouble("balance");
            System.out.printf("%d | %s | %.2f%n", id, name, balance);
        }
    }

} catch (SQLException e) {
    e.printStackTrace();
}

Statement vs PreparedStatement

StatementPreparedStatement
SQL-инъекции❌ Уязвим✅ Защищён
СкоростьМедленнееБыстрее (предкомпиляция)
ПараметрыКонкатенация строк? и setXxx()
ЧитаемостьХужеЛучше

SQL-инъекция — почему Statement опасен:

// ❌ Опасно — Statement + конкатенация
String name = "admin' OR '1'='1";
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery(
    "SELECT * FROM users WHERE name = '" + name + "'"
);
// Получится: WHERE name = 'admin' OR '1'='1' → вернёт ВСЕХ!

// ✅ Безопасно — PreparedStatement
String sql = "SELECT * FROM users WHERE name = ?";
PreparedStatement stmt = conn.prepareStatement(sql);
stmt.setString(1, name); // драйвер сам экранирует

Транзакции в JDBC

Транзакция — набор операций, которые либо все выполняются, либо все откатываются (ACID).

ACID:

БукваСвойствоЗначение
AAtomicityВсё или ничего
CConsistencyДанные всегда корректны
IIsolationТранзакции не мешают друг другу
DDurabilityРезультат сохраняется после сбоя
Connection conn = DriverManager.getConnection(url, user, password);
try {
    conn.setAutoCommit(false); // начало транзакции

    // Снять со счёта
    PreparedStatement stmt1 = conn.prepareStatement(
        "UPDATE accounts SET balance = balance - ? WHERE id = ?");
    stmt1.setDouble(1, 500.00);
    stmt1.setInt(2, 1);
    stmt1.executeUpdate();

    // Зачислить на счёт
    PreparedStatement stmt2 = conn.prepareStatement(
        "UPDATE accounts SET balance = balance + ? WHERE id = ?");
    stmt2.setDouble(1, 500.00);
    stmt2.setInt(2, 2);
    stmt2.executeUpdate();

    conn.commit(); // всё хорошо — фиксируем
} catch (SQLException e) {
    conn.rollback(); // ошибка — откатываем
    throw e;
} finally {
    conn.setAutoCommit(true);
    conn.close();
}
