⚖ equals() и hashCode()

Одна из самых частых тем на собесе. Контракт, коллизии, правильная реализация — всё здесь.

Контракт equals() и hashCode()

Три главных правила:

  1. Если два объекта равны по equals(), их hashCode() обязаны быть одинаковыми
  2. Обратное необязательно: одинаковый hashCode ≠ объекты равны (это коллизия)
  3. Переопределяешь equals() — всегда переопределяй hashCode()
Контракт equals() и hashCode(): равные объекты должны иметь одинаковый хэш-код. Если переопределить только equals(), объекты потеряются в HashSet/HashMap. Всегда переопределяйте оба метода вместе.

Что будет, если нарушить контракт

Объекты потеряются в хэш-коллекциях (HashSet, HashMap).

class Person {
    String name;
    Person(String name) { this.name = name; }

    @Override
    public boolean equals(Object o) {
        return name.equals(((Person) o).name);
    }
    // hashCode() НЕ переопределён!
}

Set<Person> set = new HashSet<>();
set.add(new Person("Иван"));

System.out.println(set.contains(new Person("Иван"))); // false!
// Потому что hashCode разный → разная корзина → equals даже не вызывается

Как это работает в HashMap:

  1. Вычисляется hashCode() ключа
  2. По хэшу определяется корзина (bucket)
  3. Внутри корзины идёт сравнение через equals()
  4. Если hashCode разный — до equals() дело не доходит

Ошибка: перегрузка вместо переопределения

Если написать equals(Person p) вместо equals(Object o) — это перегрузка, а не переопределение. Коллекции вызовут equals(Object) из Object, который сравнивает ссылки.

// ❌ Неправильно — перегрузка!
public boolean equals(Person p) {
    return name.equals(p.name);
}

// ✅ Правильно — переопределение!
@Override
public boolean equals(Object o) {
    if (!(o instanceof Person)) return false;
    Person p = (Person) o;
    return name.equals(p.name);
}

// Проверка:
Person p1 = new Person("Иван");
Object p2 = new Person("Иван");
p1.equals(p2); // true при правильном, false при перегрузке!

Всегда ставь @Override — компилятор подсветит ошибку.

Пять правил equals() — контракт

ПравилоЗначение
Рефлексивностьx.equals(x) всегда true
Симметричностьx.equals(y) ⇄ y.equals(x)
Транзитивностьесли x.equals(y) и y.equals(z) → x.equals(z)
КонсистентностьРезультат не меняется при многократном вызове
null-безопасностьx.equals(null) всегда false

Шаблон правильной реализации

public class Student {
    private String name;
    private int age;

    // конструктор, геттеры...

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                        // та же ссылка — точно равны
        if (o == null || getClass() != o.getClass())       // null или другой класс
            return false;
        Student student = (Student) o;                     // приводим тип
        return age == student.age                          // примитивы через ==
            && Objects.equals(name, student.name);         // объекты через Objects.equals
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);                    // все поля из equals
    }
}

Почему именно так:

  • this == o — быстрая проверка на ту же ссылку
  • getClass() != o.getClass() — строгая проверка класса (альтернатива: instanceof)
  • Objects.equals(a, b) — безопасное сравнение (учитывает null)
  • Objects.hash(...) — генерирует хэш на основе всех полей

getClass() vs instanceof:

ПодходПлюсМинус
getClass() != o.getClass() Строго: наследники не равны родителю Может сломать LSP (принцип подстановки)
!(o instanceof MyClass) Гибко: наследник может быть равен родителю Может нарушить симметричность

Коллизии

Коллизия — когда у двух разных объектов одинаковый hashCode(). Это нормально, но чем реже — тем лучше.

// Плохой hashCode — всегда 1, все объекты в одной корзине → O(n)
@Override
public int hashCode() {
    return 1; // формально правильно, но ужасно медленно
}

// Хороший hashCode — равномерное распределение → O(1)
@Override
public int hashCode() {
    return Objects.hash(name, age);
}

Если коллизия случилась — объекты попадают в одну корзину и сравниваются через equals(). HashMap из O(1) превращается в O(n) для этой корзины.
