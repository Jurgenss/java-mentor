🔄 CI/CD — Continuous Integration / Continuous Delivery

CI/CD — практика автоматизации сборки, тестирования и деплоя. На джуна спросят: "Что такое CI/CD? Какие инструменты знаете?"

CI (Continuous Integration) — непрерывная интеграция

Суть: разработчики сливают код в общую ветку несколько раз в день. Каждый пуш автоматически собирается и тестируется.

Разработчик пушит код → GitHub/GitLab
                            ↓
                    CI-сервер (Jenkins/GitHub Actions)
                            ↓
                    1. mvn clean compile
                    2. mvn test (все тесты)
                    3. mvn package (сборка JAR)
                            ↓
                    Успех ✅ → можно деплоить
                    Провал ❌ → уведомление в Slack/почту, билд красный
CI (Continuous Integration) — практика частого слияния кода с автоматической сборкой и тестами. Позволяет быстро находить конфликты и ошибки. Каждый коммит проверяется: код компилируется, тесты проходят. Если что-то сломалось — узнаём сразу, а не перед релизом.

GitHub Actions — пример для Java

CI/CD встроен в GitHub. Конфигурация — YAML-файл в репозитории.

# .github/workflows/build.yml
name: Build and Test

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'

      - name: Build with Maven
        run: mvn clean package

      - name: Run tests
        run: mvn test

      - name: Upload JAR artifact
        uses: actions/upload-artifact@v4
        with:
          name: app-jar
          path: target/*.jar

Полный CI/CD с Docker и деплоем:

# .github/workflows/deploy.yml
name: Deploy to Server

on:
  push:
    branches: [ main ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build Docker image
        run: docker build -t myapp:${{ github.sha }} .

      - name: Push to Docker Registry
        run: |
          docker tag myapp:${{ github.sha }} registry.example.com/myapp:latest
          docker push registry.example.com/myapp:latest

      - name: Deploy to server via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_KEY }}
          script: |
            docker pull registry.example.com/myapp:latest
            docker compose -f /opt/myapp/docker-compose.yml up -d

DevOps — общая картина

DevOps = Development (разработка) + Operations (эксплуатация)

Практики DevOps:
├── CI/CD (автоматизация сборки и деплоя)
├── IaC (Infrastructure as Code — Terraform, Ansible)
├── Мониторинг (Prometheus, Grafana)
├── Логирование (ELK: Elasticsearch + Logstash + Kibana)
└── Контейнеризация (Docker + Kubernetes)
