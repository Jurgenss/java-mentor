📝 String в Java

Строки — самый используемый класс в Java. На собесе спросят про immutable, String Pool и отличие от StringBuilder.

Почему String неизменяемый (immutable)

Три главные причины:

  1. Безопасность: строки используются в путях к файлам, паролях, URL. Если бы их можно было изменить после проверки — дыра в безопасности.
  2. Потокобезопасность: неизменяемый объект можно использовать в любом количестве потоков без синхронизации.
  3. String Pool: возможность кешировать и переиспользовать одинаковые строки экономит память.
Строки в Java неизменяемы по трём причинам: безопасность (нельзя подменить после проверки), потокобезопасность и возможность кеширования в String Pool для экономии памяти.

String Pool (пул строк)

Специальная область в куче, где хранятся строки, созданные через литералы.

String a = "Hello";              // попадает в пул
String b = "Hello";              // находит там же → та же ссылка
String c = new String("Hello");  // новый объект ВНЕ пула
String d = c.intern();           // возвращает ссылку из пула

System.out.println(a == b);      // true  — один объект
System.out.println(a == c);      // false — разные объекты
System.out.println(a.equals(c)); // true  — equals сравнивает символы
System.out.println(a == d);      // true  — intern вернул ссылку из пула

Как это работает:

  • "Hello" — JVM проверяет пул: есть? → вернуть ссылку. Нет? → создать в пуле
  • new String("Hello") — всегда новый объект в куче, не в пуле
  • intern() — вернуть ссылку из пула (если нет — создать)
При создании через литерал строка попадает в String Pool. При создании через new String() — новый объект в куче, не в пуле. Метод intern() возвращает ссылку из пула. == сравнивает ссылки, equals() сравнивает символы.

Важно: все методы возвращают НОВУЮ строку

Исходная строка никогда не меняется!

String s = "Java";
s.concat("Rush");       // создаёт "JavaRush", но s не меняется!
System.out.println(s);  // "Java"

s = s.concat("Rush");   // теперь s указывает на новый объект
System.out.println(s);  // "JavaRush"

Почему StringBuilder быстрее:

// Плохо — каждый += создаёт новый объект String (10 объектов!)
String s = "";
for (int i = 0; i < 10; i++) {
    s += i; // новый String на каждой итерации
}

// Хорошо — один объект StringBuilder, меняем внутри
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 10; i++) {
    sb.append(i); // меняем существующий объект
}
String result = sb.toString(); // один раз в String

Конкатенация строк — как на самом деле

Современная Java оптимизирует + через invokedynamic и StringConcatFactory, но в циклах всё равно лучше StringBuilder.

// Компилятор превращает это:
String s = "a" + "b" + "c";

// Примерно в это (упрощённо):
String s = "abc"; // константы склеиваются на этапе компиляции

// А это:
String s = a + b + c; // переменные
// Превращается в StringBuilder (через invokedynamic в Java 9+)
