📄 Сериализация и Jackson

Сериализация — превращение объекта в поток байтов/JSON для передачи по сети или сохранения. Jackson — самая популярная библиотека для JSON в Java.

Что такое сериализация

Сериализация — объект → байты/JSON/XML (сохранить или передать).

Десериализация — байты/JSON/XML → объект (восстановить).

Java-объект:                     JSON:
User user = new User(             {
    "Иван",                            "name": "Иван",
    25,                                "age": 25,
    "ivan@mail.ru"                     "email": "ivan@mail.ru"
);                                }

Сериализация:   user  → Jackson → {"name":"Иван","age":25,"email":"ivan@mail.ru"}
Десериализация: JSON  → Jackson → new User("Иван", 25, "ivan@mail.ru")
Сериализация — процесс преобразования объекта в формат для хранения/передачи (JSON, XML, байты). Десериализация — обратный процесс. Jackson — самая популярная библиотека для работы с JSON в Java. В Spring Boot подключается автоматически со starter-web.

Jackson — основная библиотека для JSON

В Spring Boot Jackson подключается автоматически со spring-boot-starter-web. Никаких дополнительных зависимостей.

ObjectMapper — главный класс Jackson:

ObjectMapper mapper = new ObjectMapper(); // в Spring — бин, можно @Autowired

// Объект → JSON (сериализация)
User user = new User("Иван", 25, "ivan@mail.ru");
String json = mapper.writeValueAsString(user);
// → {"name":"Иван","age":25,"email":"ivan@mail.ru"}

// JSON → Объект (десериализация)
String jsonInput = "{\"name\":\"Пётр\",\"age\":30,\"email\":\"petr@mail.ru\"}";
User user2 = mapper.readValue(jsonInput, User.class);
// → User(name=Пётр, age=30, email=petr@mail.ru)

Аннотации Jackson

АннотацияЧто делаетПример
@JsonProperty Задать имя поля в JSON @JsonProperty("full_name") String name;
@JsonIgnore Исключить поле из JSON @JsonIgnore String password;
@JsonFormat Формат даты/числа @JsonFormat(pattern="dd.MM.yyyy") LocalDate date;
@JsonInclude Не включать null-поля @JsonInclude(Include.NON_NULL) (на класс)
@JsonIgnoreProperties Игнорировать неизвестные поля при десериализации @JsonIgnoreProperties(ignoreUnknown = true)
@JsonAlias Альтернативные имена для десериализации @JsonAlias({"userName", "login"}) String name;
@JsonPropertyOrder Порядок полей в JSON @JsonPropertyOrder({"name", "age", "email"})

Пример класса с аннотациями:

@JsonIgnoreProperties(ignoreUnknown = true) // лишние поля из JSON — игнорируем
@JsonInclude(JsonInclude.Include.NON_NULL)   // null-поля — не выводим
public class User {

    private Long id;

    @JsonProperty("full_name")                 // в JSON будет "full_name"
    @JsonAlias({"userName", "login"})          // при чтении примет и "userName", и "login"
    private String name;

    @JsonIgnore                                // пароль НИКОГДА не попадёт в JSON
    private String password;

    @JsonFormat(pattern = "dd.MM.yyyy")
    private LocalDate birthDate;

    // геттеры/сеттеры...
}

Настройка Jackson глобально (application.properties):

# Не выводить null-поля
spring.jackson.default-property-inclusion=non_null

# Формат даты
spring.jackson.date-format=dd.MM.yyyy

# Не падать, если в JSON есть неизвестные поля
spring.jackson.deserialization.fail-on-unknown-properties=false

# Красивый отступ в JSON
spring.jackson.serialization.indent-output=true

Сериализация в Java (интерфейс Serializable)

Встроенный механизм Java — преобразование объекта в поток байтов. Используется реже, чем JSON.

public class User implements java.io.Serializable {
    private static final long serialVersionUID = 1L; // обязательно для версионности!
    private String name;
    private transient String password; // transient — НЕ сериализуется
}

// Сериализация (в файл)
try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("user.ser"))) {
    oos.writeObject(user);
}

// Десериализация (из файла)
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("user.ser"))) {
    User user = (User) ois.readObject();
}

serialVersionUID — зачем:

  • Если не указать — Java сгенерирует сама (на основе полей класса)
  • При изменении класса (добавили поле) — UID изменится → старые файлы не прочитаются
  • Указываем явно — контролируем версионность

DTO и сериализация

DTO (Data Transfer Object) — отдельный класс для передачи данных. Позволяет не тянуть лишние поля и скрыть структуру БД.

// ❌ Плохо — отдаём Entity напрямую (пароль может утечь, циклические ссылки)
@GetMapping("/{id}")
public User getUser(@PathVariable Long id) {
    return userRepo.findById(id).orElseThrow();
}

// ✅ Хорошо — отдаём DTO
@GetMapping("/{id}")
public UserDto getUser(@PathVariable Long id) {
    User user = userRepo.findById(id).orElseThrow();
    return new UserDto(user.getName(), user.getEmail()); // пароль не попадёт
}
