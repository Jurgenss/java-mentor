🎨 Паттерны проектирования

Паттерны — проверенные решения типовых задач. На собесе на джуна обычно спрашивают Singleton, Factory, Builder, а также знание категорий (порождающие, структурные, поведенческие).

Три категории паттернов

КатегорияЗадачаПримеры
Порождающие (Creational)Как создавать объекты гибко и удобноSingleton, Factory Method, Builder, Prototype
Структурные (Structural)Как организовать отношения между классамиAdapter, Decorator, Proxy, Facade
Поведенческие (Behavioral)Как организовать взаимодействие объектовObserver, Strategy, Template Method, Chain of Responsibility

1. Singleton (Одиночка) — порождающий

Суть: гарантирует, что у класса есть только ОДИН экземпляр, и предоставляет глобальную точку доступа к нему.

Когда: конфигурация приложения, пул соединений, логгер, кеш.

Потокобезопасный Singleton (DCL — Double-Checked Locking):

public class DatabaseConnection {
    // volatile — обязательно! Иначе другой поток может увидеть частично созданный объект
    private static volatile DatabaseConnection instance;

    private DatabaseConnection() {
        // приватный конструктор — нельзя создать извне
    }

    public static DatabaseConnection getInstance() {
        if (instance == null) {                    // первая проверка (без блокировки)
            synchronized (DatabaseConnection.class) {
                if (instance == null) {            // вторая проверка (внутри блокировки)
                    instance = new DatabaseConnection();
                }
            }
        }
        return instance;
    }
}

Singleton через Enum (самый надёжный):

public enum Config {
    INSTANCE;

    private String appName = "MyApp";

    public String getAppName() { return appName; }
    public void setAppName(String name) { this.appName = name; }
}

// Использование:
Config.INSTANCE.getAppName();
  • ✅ Защита от рефлексии (нельзя создать второй экземпляр)
  • ✅ Защита от сериализации/десериализации
  • ✅ Потокобезопасность из коробки
Singleton гарантирует единственный экземпляр класса. Используется для конфигураций, пулов соединений, логгеров. Лучшая реализация в Java — через enum: защита от рефлексии, сериализации и потокобезопасность из коробки.

2. Factory Method (Фабричный метод) — порождающий

Суть: выносит создание объектов в отдельный метод/класс. Клиент не знает конкретный класс — работает через интерфейс.

Когда: нужно создавать разные типы объектов в зависимости от условий.

// Продукт — интерфейс
interface Payment {
    void pay(BigDecimal amount);
}

// Конкретные продукты
class CardPayment implements Payment {
    public void pay(BigDecimal amount) {
        System.out.println("Оплата картой: " + amount);
    }
}

class QrPayment implements Payment {
    public void pay(BigDecimal amount) {
        System.out.println("Оплата по QR: " + amount);
    }
}

// Фабрика
class PaymentFactory {
    public static Payment create(String type) {
        return switch (type) {
            case "CARD" -> new CardPayment();
            case "QR" -> new QrPayment();
            default -> throw new IllegalArgumentException("Неизвестный тип: " + type);
        };
    }
}

// Клиент — не знает про CardPayment и QrPayment
Payment payment = PaymentFactory.create("CARD");
payment.pay(new BigDecimal("1000"));

3. Builder (Строитель) — порождающий

Суть: пошаговое создание сложного объекта. Вместо конструктора с 10 параметрами — цепочка методов.

Когда: у объекта много полей, часть из них опциональна.

public class User {
    private final String name;       // обязательно
    private final String email;      // обязательно
    private final int age;           // опционально
    private final String phone;      // опционально
    private final String address;    // опционально

    private User(Builder builder) {
        this.name = builder.name;
        this.email = builder.email;
        this.age = builder.age;
        this.phone = builder.phone;
        this.address = builder.address;
    }

    // Builder
    public static class Builder {
        private final String name;   // обязательно — в конструкторе Builder'а
        private final String email;
        private int age;
        private String phone;
        private String address;

        public Builder(String name, String email) {
            this.name = name;
            this.email = email;
        }

        public Builder age(int age) { this.age = age; return this; }
        public Builder phone(String phone) { this.phone = phone; return this; }
        public Builder address(String address) { this.address = address; return this; }

        public User build() {
            return new User(this);
        }
    }
}

// Использование
User user = new User.Builder("Иван", "ivan@mail.ru")
    .age(25)
    .phone("+79001234567")
    .build();

Lombok упрощает:

@Builder
public class User {
    private final String name;
    private final String email;
    private final int age;
    private final String phone;
}

User user = User.builder()
    .name("Иван")
    .email("ivan@mail.ru")
    .age(25)
    .build();

4. Adapter (Адаптер) — структурный

Суть: позволяет объектам с несовместимыми интерфейсами работать вместе (как переходник для розетки).

Когда: нужно использовать сторонний класс, но его интерфейс не подходит.

// Сторонний класс (не можем менять)
class ThirdPartyLogger {
    void logMessage(String msg) {
        System.out.println("[3rd-party] " + msg);
    }
}

// Наш интерфейс
interface Logger {
    void info(String message);
    void error(String message);
}

// Адаптер
class LoggerAdapter implements Logger {
    private final ThirdPartyLogger adaptee;

    public LoggerAdapter(ThirdPartyLogger adaptee) {
        this.adaptee = adaptee;
    }

    @Override
    public void info(String message) {
        adaptee.logMessage("INFO: " + message);
    }

    @Override
    public void error(String message) {
        adaptee.logMessage("ERROR: " + message);
    }
}

// Использование — везде работаем через Logger, не зная про ThirdPartyLogger
Logger logger = new LoggerAdapter(new ThirdPartyLogger());
logger.info("Приложение запущено");

5. Decorator (Декоратор) — структурный

Суть: динамически добавляет новую функциональность объекту, оборачивая его. В отличие от наследования — на лету.

Когда: нужно добавить поведение объекту без изменения его класса.

// Базовый интерфейс
interface Coffee {
    String getDescription();
    double getCost();
}

// Базовый класс
class SimpleCoffee implements Coffee {
    public String getDescription() { return "Кофе"; }
    public double getCost() { return 100.0; }
}

// Декоратор — обёртка
abstract class CoffeeDecorator implements Coffee {
    protected final Coffee coffee; // оборачиваемый объект

    public CoffeeDecorator(Coffee coffee) { this.coffee = coffee; }
}

// Конкретные декораторы
class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee coffee) { super(coffee); }
    public String getDescription() { return coffee.getDescription() + " + молоко"; }
    public double getCost() { return coffee.getCost() + 30.0; }
}

class SugarDecorator extends CoffeeDecorator {
    public SugarDecorator(Coffee coffee) { super(coffee); }
    public String getDescription() { return coffee.getDescription() + " + сахар"; }
    public double getCost() { return coffee.getCost() + 5.0; }
}

// Использование — можно комбинировать как угодно!
Coffee coffee = new SimpleCoffee();               // Кофе — 100₽
coffee = new MilkDecorator(coffee);               // + молоко — 130₽
coffee = new SugarDecorator(coffee);              // + сахар — 135₽
System.out.println(coffee.getDescription());      // Кофе + молоко + сахар

Где в Java: BufferedReader — декоратор для Reader, BufferedInputStream — декоратор для InputStream.

6. Observer (Наблюдатель) — поведенческий

Суть: одни объекты (наблюдатели) подписываются на события другого объекта (издателя). Когда издатель меняется — все наблюдатели получают уведомление.

Когда: рассылка уведомлений, обновление UI при изменении данных.

// Издатель
class NewsAgency {
    private final List<Observer> observers = new ArrayList<>();
    private String news;

    public void subscribe(Observer observer) { observers.add(observer); }
    public void unsubscribe(Observer observer) { observers.remove(observer); }

    public void setNews(String news) {
        this.news = news;
        notifyObservers(); // оповещаем всех
    }

    private void notifyObservers() {
        for (Observer o : observers) {
            o.update(news);
        }
    }
}

// Наблюдатель
interface Observer {
    void update(String news);
}

class EmailSubscriber implements Observer {
    private final String name;
    public EmailSubscriber(String name) { this.name = name; }
    public void update(String news) {
        System.out.println(name + " получил новость: " + news);
    }
}

// Использование
NewsAgency agency = new NewsAgency();
agency.subscribe(new EmailSubscriber("Иван"));
agency.subscribe(new EmailSubscriber("Мария"));
agency.setNews("Java 25 вышел!"); // оба получат уведомление

7. Strategy (Стратегия) — поведенческий

Суть: семейство алгоритмов, каждый в своём классе. Можно переключать алгоритм на лету.

Когда: разные способы сортировки, расчёта скидки, валидации.

// Стратегия — интерфейс
interface DiscountStrategy {
    BigDecimal apply(BigDecimal price);
}

// Конкретные стратегии
class NoDiscount implements DiscountStrategy {
    public BigDecimal apply(BigDecimal price) { return price; }
}

class SeasonalDiscount implements DiscountStrategy {
    public BigDecimal apply(BigDecimal price) {
        return price.multiply(new BigDecimal("0.8")); // -20%
    }
}

class VipDiscount implements DiscountStrategy {
    public BigDecimal apply(BigDecimal price) {
        return price.multiply(new BigDecimal("0.5")); // -50%
    }
}

// Контекст
class PriceCalculator {
    private DiscountStrategy strategy;

    public void setStrategy(DiscountStrategy strategy) {
        this.strategy = strategy;
    }

    public BigDecimal calculate(BigDecimal price) {
        return strategy.apply(price);
    }
}

// Использование
PriceCalculator calc = new PriceCalculator();

calc.setStrategy(new NoDiscount());
calc.calculate(new BigDecimal("1000")); // 1000

calc.setStrategy(new SeasonalDiscount());
calc.calculate(new BigDecimal("1000")); // 800 — переключили на лету!

Шпаргалка: какой паттерн когда

ПроблемаПаттерн
Нужен только один экземпляр классаSingleton
Создание разных типов объектов по условиюFactory Method
Много параметров у конструктораBuilder
Несовместимые интерфейсыAdapter
Добавить поведение объекту без изменения кодаDecorator
Уведомлять подписчиков о событияхObserver
Переключать алгоритмы на летуStrategy
Сложная система → простой интерфейсFacade
Доступ к удалённому объекту как к локальномуProxy
