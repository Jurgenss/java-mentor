🔧 Git — основные команды

Git — система контроля версий. На собесе спросят базовые команды и разницу между merge и rebase.

Базовые команды

КомандаЧто делает
git initСоздать новый локальный репозиторий
git clone <url>Клонировать удалённый репозиторий
git statusПоказать состояние файлов (изменённые, новые, staged)
git add <file>Добавить файл в индекс (staging area)
git add .Добавить ВСЕ изменения в индекс
git commit -m "..."Создать коммит с сообщением
git pushОтправить коммиты на удалённый сервер
git pullЗабрать изменения с сервера (= fetch + merge)
git fetchЗабрать изменения, но НЕ сливать (без merge)
git logИстория коммитов
git log --onelineИстория коммитов (компактно, по одному на строку)
git diffПоказать изменения (не staged)
git diff --stagedПоказать изменения в staged
Рабочий процесс: git add (добавить в индекс) → git commit (зафиксировать) → git push (отправить на сервер). git pull = git fetch + git merge.

Три состояния файлов в Git

Рабочая директория        Staging Area (индекс)       Репозиторий
(Working Directory)        (git add)                  (git commit)
     ↓                         ↓                          ↓
  изменил файл  →  git add  →  файл в staged  →  git commit  →  коммит сохранён

Ветки (branches)

КомандаЧто делает
git branchПоказать список локальных веток
git branch -aПоказать ВСЕ ветки (локальные + удалённые)
git branch <name>Создать новую ветку
git checkout <branch>Переключиться на ветку
git checkout -b <name>Создать И переключиться на новую ветку
git switch <branch>Переключиться (Git 2.23+, более понятный аналог checkout)
git switch -c <name>Создать и переключиться
git branch -d <name>Удалить локальную ветку (если слита)
git branch -D <name>Удалить локальную ветку (даже если не слита)
git push origin --delete <name>Удалить удалённую ветку

Merge vs Rebase

Оба способа объединить изменения из одной ветки в другую. Разница — в истории коммитов.

Merge:

# Находясь в main:
git merge feature/login

# Создаёт merge-коммит. История сохраняется как есть.
# main:    A---B---C---M (merge commit)
#                \     /
# feature/login:  D---E
  • ✅ Сохраняет реальную историю
  • ✅ Безопасно для общих веток
  • ❌ Много merge-коммитов "загрязняют" историю

Rebase:

# Находясь в feature/login:
git rebase main

# "Перемещает" коммиты feature/login поверх main.
# До:                  После:
# main: A---B---C      main: A---B---C
#            \                      \
# feature:    D---E                  D'---E' (новые коммиты!)
  • ✅ Чистая линейная история
  • ❌ Переписывает историю — НЕ использовать в общих ветках!
  • ❌ Может вызвать конфликты на каждом коммите
MergeRebase
ИсторияСохраняется (ветвление видно)Линейная (как будто всё по порядку)
Безопасность✅ Безопасно всегда⚠ Только для личных веток!
КонфликтыРешаются один разМогут быть на каждом коммите
Командаgit merge branchgit rebase branch
Merge сохраняет историю и создаёт merge-коммит. Безопасен для общих веток. Rebase делает историю линейной, но переписывает коммиты — использовать ТОЛЬКО в личных ветках. Правило: rebase — для своих feature-веток перед merge в main, merge — для слияния в main.

Отмена изменений

СитуацияКоманда
Отменить изменения в файле (до add)git checkout -- <file> или git restore <file>
Убрать файл из staged (после add)git reset HEAD <file> или git restore --staged <file>
Отменить последний коммит (сохранить изменения)git reset --soft HEAD~1
Отменить последний коммит (удалить изменения)git reset --hard HEAD~1
Создать новый коммит, отменяющий измененияgit revert <commit-hash>

git stash — "спрятать" изменения

КомандаЧто делает
git stashСпрятать все незакоммиченные изменения
git stash popВернуть последние спрятанные изменения И удалить из stash
git stash applyВернуть изменения, НО оставить в stash
git stash listПосмотреть список stash'ей
git stash dropУдалить последний stash

Сценарий: работаешь в feature-ветке, нужно срочно переключиться в main. Изменения не готовы для коммита → git stash → переключился → сделал срочную задачу → вернулся → git stash pop.

Популярные workflow

Как начать новую задачу:

git checkout main                # переключиться на main
git pull                         # забрать последние изменения
git checkout -b feature/task-42  # создать ветку для задачи
# ... работаем, коммитим ...
git push -u origin feature/task-42  # отправить ветку на сервер

Как смержить свою ветку:

# Вариант 1: Через merge
git checkout main
git pull
git merge feature/task-42
git push

# Вариант 2: Через rebase + merge (чистая история)
git checkout feature/task-42
git rebase main                  # перемещаем свои коммиты поверх main
git checkout main
git merge feature/task-42        # fast-forward merge — без merge-коммита!
git push
