🚀 Spring Boot

Spring Boot — это не отдельный фреймворк, а надстройка над Spring, которая убирает boilerplate-конфигурацию.

Что такое Spring Boot

Spring Boot = Spring Framework + автоконфигурация + встроенный сервер.

Spring (без Boot)Spring Boot
НастройкаXML / Java Config, много ручной конфигурацииАвтоконфигурация, application.properties
ЗапускНужен внешний сервер (Tomcat, WildFly)Встроенный Tomcat/Jetty/Undertow
ЗависимостиПодключаем каждую вручнуюСтартеры (spring-boot-starter-*)
ДеплойWAR-файл на серверJAR-файл, запускаемый через java -jar
МониторингНастраиваем отдельноActuator из коробки
Spring Boot — это надстройка над Spring Framework. Упрощает создание приложений за счёт автоконфигурации (не нужно писать XML/Java Config для стандартных вещей), встроенного сервера (Tomcat внутри JAR) и стартеров (готовые наборы зависимостей).

@SpringBootApplication — главная аннотация

Эта аннотация объединяет три другие:

@SpringBootApplication
// Равносильно:
@Configuration        // класс может содержать @Bean-методы
@EnableAutoConfiguration  // включает автоконфигурацию
@ComponentScan        // сканирует пакет и подпакеты на бины

Точка входа:

@SpringBootApplication
public class MyApp {
    public static void main(String[] args) {
        SpringApplication.run(MyApp.class, args);
    }
}

Стартеры (Starters)

Готовые наборы зависимостей. Вместо 10 зависимостей — одна.

СтартерЧто даёт
spring-boot-starter-webSpring MVC + встроенный Tomcat + Jackson (JSON)
spring-boot-starter-data-jpaJPA + Hibernate + Spring Data JPA
spring-boot-starter-data-redisRedis
spring-boot-starter-securitySpring Security
spring-boot-starter-testJUnit 5, Mockito, AssertJ (для тестов, scope test)
spring-boot-starter-actuatorМониторинг: метрики, health-check
spring-boot-starter-validationBean Validation (Hibernate Validator)
spring-boot-starter-aopSpring AOP

Пример pom.xml:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
<!-- версия НЕ нужна — Spring Boot сам подставит совместимую -->

application.properties / application.yml

Вся конфигурация — в одном файле. Spring Boot сам подхватывает.

# Сервер
server.port=8080
server.servlet.context-path=/api

# База данных
spring.datasource.url=jdbc:postgresql://localhost:5432/bank
spring.datasource.username=postgres
spring.datasource.password=secret
spring.datasource.driver-class-name=org.postgresql.Driver

# JPA / Hibernate
spring.jpa.hibernate.ddl-auto=validate  # none, validate, update, create, create-drop
spring.jpa.show-sql=true                # показывать SQL в логах
spring.jpa.properties.hibernate.format_sql=true

# Профили
spring.profiles.active=dev  # application-dev.properties

application.yml (альтернативный формат):

spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/bank
    username: postgres
    password: secret
  jpa:
    hibernate:
      ddl-auto: validate
    show-sql: true

Автоконфигурация — как работает

  1. Spring Boot смотрит на зависимости в classpath
  2. Если есть H2 — настраивает in-memory БД
  3. Если есть PostgreSQL-драйвер — настраивает подключение к PostgreSQL
  4. Если есть spring-boot-starter-web — настраивает DispatcherServlet

Отключить автоконфигурацию:

@SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})

Actuator — мониторинг

Подключаешь стартер — получаешь endpoints для мониторинга.

EndpointЧто показывает
/actuator/healthЖив ли сервис (БД, диск, Redis)
/actuator/infoИнформация о приложении (версия, автор)
/actuator/metricsМетрики (память, запросы, треды)
/actuator/envПеременные окружения
/actuator/loggersИзменить уровень логирования на лету

Профили (Profiles)

Разные конфигурации для разных сред (dev, test, prod).

# application.properties (общая)
spring.application.name=myapp

# application-dev.properties (для разработки)
server.port=8080
spring.jpa.hibernate.ddl-auto=update

# application-prod.properties (для продакшена)
server.port=80
spring.jpa.hibernate.ddl-auto=validate

# Запуск с профилем:
# java -jar myapp.jar --spring.profiles.active=prod

Тонкости и best practices

  • Не используй spring.jpa.hibernate.ddl-auto=update в проде — можно сломать схему. Только validate или миграции (Flyway/Liquibase).
  • Выноси чувствительные данные (пароли, ключи) в переменные окружения, не в application.properties.
  • Для тестов — H2 in-memory база (spring-boot-starter-data-jpa автоматически настраивает).
  • Сборка: mvn clean package → получаешь JAR со встроенным Tomcat → java -jar target/myapp.jar.
