🧵 Многопоточность в Java

Многопоточка — одна из самых сложных тем для джуна. Но базу спрашивают всегда: создание потоков, synchronized, volatile, wait/notify.

Способы создания потока

СпособПримерКогда
extends Thread new MyThread().start(); Если не нужно наследовать другой класс
implements Runnable new Thread(new MyRunnable()).start(); ✅ Предпочтительно: разделяет задачу и поток 
// Способ 1: extends Thread
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Поток: " + Thread.currentThread().getName());
    }
}
new MyThread().start();

// Способ 2: implements Runnable (лучше)
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("Поток: " + Thread.currentThread().getName());
    }
}
new Thread(new MyRunnable()).start();

// Способ 3: лямбда (Java 8+)
new Thread(() -> System.out.println("Поток из лямбды")).start();
Поток можно создать двумя способами: унаследовать Thread или реализовать Runnable. Runnable предпочтительнее — класс может наследовать что-то ещё, а задачу можно передать в пул потоков. Запуск всегда через start(), не run().

start() vs run()

start()run()
Новый поток✅ Создаёт❌ Нет, выполняется в текущем
Асинхронность✅ Да❌ Нет, синхронно
Повторный вызов❌ IllegalThreadStateException✅ Можно сколько угодно
Thread thread = new Thread(() -> System.out.println("Привет из " + Thread.currentThread().getName()));

thread.run();   // "Привет из main" — текущий поток!
thread.start(); // "Привет из Thread-0" — новый поток!
thread.start(); // ❌ IllegalThreadStateException!

Состояния потока (жизненный цикл)

NEW → (start()) → RUNNABLE → (завершил run) → TERMINATED
                   ↑   ↓
              BLOCKED (ждёт монитор)
              WAITING (ждёт notify)
              TIMED_WAITING (sleep, wait(timeout))

synchronized

Гарантирует, что в блок кода одновременно зайдёт только один поток. Решает проблему race condition.

Проблема (без synchronized):

class Counter {
    int count = 0;

    void increment() {
        count++; // НЕ атомарно! Чтение → увеличение → запись
    }
}
// 1000 потоков × 1000 вызовов → результат < 1 000 000!

Решение (с synchronized):

class Counter {
    int count = 0;

    synchronized void increment() {
        count++; // теперь только один поток за раз
    }
}

// Или через блок:
void increment() {
    synchronized (this) {
        count++;
    }
}

// Или через отдельный объект-монитор:
private final Object lock = new Object();
void increment() {
    synchronized (lock) {
        count++;
    }
}

Что даёт synchronized:

  • Атомарность — операция выполняется целиком
  • Видимость — изменения видны всем потокам
  • Блокировка — остальные потоки ждут

volatile

Гарантирует только видимость, но не атомарность. Переменная читается из основной памяти, не кешируется в потоке.

class Flag {
    volatile boolean running = true; // без volatile может не увидеть изменения!

    void stop() {
        running = false; // поток main меняет
    }

    void work() {
        while (running) { // другой поток читает
            // без volatile — может зависнуть навсегда!
        }
    }
}

synchronized vs volatile:

synchronizedvolatile
Видимость✅✅
Атомарность✅❌
Блокировка✅ (ждёт)❌ (нет)
КогдаСоставные операции (count++)Флаги, простое чтение/запись

Важно: volatile int count; count++; — не работает! Это три операции, нужен synchronized или AtomicInteger.

synchronized даёт атомарность и видимость, блокирует других. volatile — только видимость, не блокирует. Для count++ нужен synchronized или AtomicInteger. Для флагов достаточно volatile.

wait() / notify() / notifyAll()

Методы класса Object для координации потоков. Вызываются только внутри synchronized!

МетодЧто делает
wait()Усыпляет текущий поток и освобождает монитор
notify()Будит один случайный ждущий поток
notifyAll()Будит все ждущие потоки
class Store {
    private int item;
    private boolean hasItem = false;

    synchronized void put(int value) throws InterruptedException {
        while (hasItem) {
            wait(); // ждём, пока заберут товар
        }
        item = value;
        hasItem = true;
        System.out.println("Произвёл: " + value);
        notify(); // будим потребителя
    }

    synchronized int get() throws InterruptedException {
        while (!hasItem) {
            wait(); // ждём, пока появится товар
        }
        hasItem = false;
        System.out.println("Потребил: " + item);
        notify(); // будим производителя
        return item;
    }
}

Важно: wait() всегда в цикле while, а не в if — защита от ложных пробуждений (spurious wakeups).

Atomic-классы (java.util.concurrent.atomic)

Потокобезопасные обёртки для примитивов. Работают быстрее synchronized.

AtomicInteger count = new AtomicInteger(0);
count.incrementAndGet();      // ++count (атомарно)
count.getAndIncrement();      // count++ (атомарно)
count.addAndGet(10);          // count += 10
count.compareAndSet(old, new); // CAS — если old, заменить на new
