🧬 Generics (обобщения)

Generics — это способ сделать код типобезопасным. Ошибки ловятся на этапе компиляции, а не в runtime.

Зачем нужны Generics

Проблема до Generics (Java 4):

List list = new ArrayList();   // сырой тип — raw type
list.add("Привет");
list.add(123);                  // можно что угодно
list.add(new Car());

String s = (String) list.get(0); // работает
String s2 = (String) list.get(1); // ClassCastException! Там Integer

С Generics (Java 5+):

List<String> list = new ArrayList<>(); // только String!
list.add("Привет");
// list.add(123);  // ❌ Ошибка компиляции!

String s = list.get(0); // приведение не нужно

Что дают Generics:

  • ✅ Проверка типов на этапе компиляции
  • ✅ Не нужно приведение типов (cast)
  • ✅ Код самодокументируется
Generics обеспечивают типобезопасность на этапе компиляции и избавляют от явного приведения типов. Ошибка типа "положил Integer, достал как String" теперь видна сразу в IDE, а не падает в продакшене.

Обобщённый класс

public class Box<T> {
    private T item;

    public void put(T item) { this.item = item; }
    public T get() { return item; }
}

Box<String> stringBox = new Box<>();
stringBox.put("Привет");
String s = stringBox.get(); // String, без приведения!

Box<Integer> intBox = new Box<>();
intBox.put(123);
Integer i = intBox.get(); // Integer

Один класс работает с любым типом. T заменяется на конкретный тип при создании.

Обобщённый метод

public static <T> T getFirst(List<T> list) {
    return list.get(0);
}

// Вызов — компилятор сам понимает T:
List<String> names = List.of("Анна", "Иван");
String first = getFirst(names); // T = String

Wildcards (подстановочные знаки)

? — "неизвестный тип". Используется, когда мы не знаем точно, какой тип будет.

WildcardЧто означаетЧитать какПисать
List<?> Список чего угодно Object ❌ Ничего
List<? extends Number> Список Number или потомков Number ❌ Ничего
List<? super Integer> Список Integer или предков Object ✅ Integer

PECS-правило

Producer Extends, Consumer Super

Producer (производитель) — extends

Мы только читаем из структуры. Используй ? extends.

void printNumbers(List<? extends Number> list) {
    for (Number n : list) {           // ✅ читаем как Number
        System.out.println(n);
    }
    // list.add(10);                  // ❌ нельзя! Не знаем точный тип
}

Consumer (потребитель) — super

Мы только пишем в структуру. Используй ? super.

void addNumbers(List<? super Integer> list) {
    list.add(10);                      // ✅ можно добавить Integer
    list.add(20);
    // Integer x = list.get(0);        // ❌ возвращается Object
}

extends vs super — наглядный пример

// ? extends Number — подходят Number, Integer, Double (вниз по иерархии)
List<? extends Number> list1 = new ArrayList<Integer>(); // ✅
List<? extends Number> list2 = new ArrayList<Double>();  // ✅
List<? extends Number> list3 = new ArrayList<Number>();  // ✅
// List list4 = new ArrayList
