🔄 Рекурсия в Java

Рекурсия — это когда метод вызывает сам себя. На собесе спросят: базовый случай, стек вызовов, StackOverflowError, когда применять.

Что такое рекурсия

Рекурсивный метод решает задачу, сводя её к меньшей версии самой себя.

  • Базовый случай — условие остановки (иначе бесконечный цикл)
  • Рекурсивный случай — вызов метода с уменьшенной задачей
// Простейший пример: факториал
public static long factorial(int n) {
    if (n <= 1) return 1;               // базовый случай
    return n * factorial(n - 1);        // рекурсивный случай
}
Рекурсия — метод вызывает сам себя с уменьшенной задачей. Обязательно нужен базовый случай для остановки. Без него — StackOverflowError. Каждый вызов создаёт новый фрейм в стеке, при глубокой рекурсии стек переполняется.

Как работает стек вызовов

factorial(3)
  → factorial(2)
      → factorial(1)  // базовый случай, возврат 1
      ← 2 * 1 = 2
  ← 3 * 2 = 6

Каждый вызов "замирает" и ждёт результата от меньшего вызова. Память для всех промежуточных вызовов хранится в стеке.

Классические задачи на рекурсию

1. Числа Фибоначчи

public static long fib(int n) {
    if (n <= 1) return n;               // базовый случай
    return fib(n - 1) + fib(n - 2);     // два рекурсивных вызова
}
// fib(0)=0, fib(1)=1, fib(2)=1, fib(3)=2, fib(4)=3, fib(5)=5
// ⚠ Чистая рекурсия — O(2^n), очень медленно для n > 40!

2. Ханойские башни

public static void hanoi(int n, char from, char inter, char to) {
    if (n == 1) {
        System.out.println("Disk 1 from " + from + " to " + to);
    } else {
        hanoi(n - 1, from, to, inter);
        System.out.println("Disk " + n + " from " + from + " to " + to);
        hanoi(n - 1, inter, from, to);
    }
}

Перенести n дисков с from на to, используя inter как вспомогательный. Количество ходов: 2ⁿ - 1.

3. Обход дерева (файловая система)

public static long getFolderSize(File folder) {
    long size = 0;
    for (File file : folder.listFiles()) {
        if (file.isFile()) size += file.length();
        else size += getFolderSize(file); // рекурсия для подпапки
    }
    return size;
}

Самое частое применение рекурсии в реальных проектах.

4. Бинарный поиск (рекурсивно)

public static int binarySearch(int[] arr, int target, int left, int right) {
    if (left > right) return -1;                    // не найдено
    int mid = left + (right - left) / 2;
    if (arr[mid] == target) return mid;
    if (arr[mid] > target)
        return binarySearch(arr, target, left, mid - 1);
    else
        return binarySearch(arr, target, mid + 1, right);
}

Опасности рекурсии

StackOverflowError

Глубина стека JVM ограничена (~1-10 тыс. вызовов). Если рекурсия слишком глубокая — стек переполняется.

// Плохо: вызовет StackOverflowError при глубоком дереве
public void traverse(TreeNode node) {
    if (node == null) return;
    traverse(node.left);
    traverse(node.right);
}

Экспоненциальная сложность

Пример: наивный Фибоначчи. Каждый вызов порождает два новых — дерево вызовов растёт лавинообразно.

Решение проблем:

ПроблемаРешение
Глубокая рекурсияЦикл + явный стек (Stack/Deque)
Экспоненциальная сложностьМемоизация (кеширование результатов)
Хвостовая рекурсияTrampoline-паттерн (JVM не оптимизирует)

Мемоизация Фибоначчи:

private static Map<Integer, Long> memo = new HashMap<>();

public static long fibMemo(int n) {
    if (n <= 1) return n;
    if (memo.containsKey(n)) return memo.get(n);
    long result = fibMemo(n - 1) + fibMemo(n - 2);
    memo.put(n, result);
    return result;
}
// Теперь O(n) вместо O(2^n)!

Замена рекурсии на цикл со стеком:

// Было — рекурсия (может упасть)
public long getFolderSize(File folder) { ... }

// Стало — цикл + стек (безопасно)
public long getFolderSizeIterative(File root) {
    long size = 0;
    Stack<File> stack = new Stack<>();
    stack.push(root);
    while (!stack.isEmpty()) {
        File current = stack.pop();
        for (File file : current.listFiles()) {
            if (file.isFile()) size += file.length();
            else stack.push(file);
        }
    }
    return size;
}
