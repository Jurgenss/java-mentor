🔄 Рекурсия — полный разбор

Рекурсия — метод, который вызывает сам себя. Используется для задач, которые можно свести к меньшей копии исходной: деревья, графы, сортировки, комбинаторика. На собеседовании спросят обязательно.

Два обязательных элемента рекурсии

ЭлементОписаниеПример (факториал)
Базовый случайУсловие остановки, без него — бесконечный цикл и StackOverflowErrorif (n <= 1) return 1;
Рекурсивный случайСведение задачи к меньшей и вызов себя с уменьшенным параметромreturn n * factorial(n - 1);
Рекурсивный метод должен иметь базовый случай (условие выхода) и рекурсивный случай (вызов себя с уменьшенной задачей). Иначе произойдёт переполнение стека — StackOverflowError.

Как работает стек вызовов

Каждый вызов метода создаёт фрейм в стеке — область памяти, где хранятся параметры и адрес возврата. Когда метод завершается, фрейм удаляется, и управление возвращается в точку вызова.

Факториал 4: пошаговая визуализация

// Вызов factorial(4) factorial(4) │ ожидает: 4 * factorial(3) │ ├─> factorial(3) │ │ ожидает: 3 * factorial(2) │ │ │ ├─> factorial(2) │ │ │ ожидает: 2 * factorial(1) │ │ │ │ │ └─> factorial(1) │ │ └─ возвращает 1 (базовый случай) │ │ возвращает 2 * 1 = 2 │ │ │ возвращает 3 * 2 = 6 │ возвращает 4 * 6 = 24

Стек растёт вниз (новые вызовы добавляются), а результат «всплывает» вверх.

Дерево рекурсии: числа Фибоначчи

Наивная рекурсия порождает экспоненциальное количество вызовов — O(2n).

fib(5) ├── fib(4) │ ├── fib(3) │ │ ├── fib(2) │ │ │ ├── fib(1) → 1 │ │ │ └── fib(0) → 0 │ │ └── fib(1) → 1 │ └── fib(2) │ ├── fib(1) → 1 │ └── fib(0) → 0 └── fib(3) ├── fib(2) │ ├── fib(1) → 1 │ └── fib(0) → 0 └── fib(1) → 1 // fib(2) вычисляется 3 раза! Отсюда и неэффективность.

Мемоизация — спасение от повторных вычислений

private static Map<Integer, Long> memo = new HashMap<>();

public static long fibMemo(int n) {
    if (n <= 1) return n;
    if (memo.containsKey(n)) return memo.get(n);
    long result = fibMemo(n - 1) + fibMemo(n - 2);
    memo.put(n, result);
    return result;
}
// Теперь O(n) вместо O(2^n)!

С мемоизацией каждый `fib(k)` вычисляется ровно один раз и сохраняется в HashMap.

Ханойские башни — пошаговый разбор (n = 3)

Задача: перенести башню из 3 дисков с A на C, используя B как вспомогательный.

doTowers(3, A, B, C) Цель: A → C │ ├─ doTowers(2, A, C, B) Шаг 1: переносим 2 диска с A на B (через C) │ ├─ doTowers(1, A, B, C) │ Базовый: Disk 1 from A to C │ ├─ Disk 2 from A to B │ Центральный диск │ └─ doTowers(1, C, A, B) │ Базовый: Disk 1 from C to B │ ├─ Disk 3 from A to C Шаг 2: переносим самый большой диск │ └─ doTowers(2, B, A, C) Шаг 3: переносим 2 диска с B на C (через A) ├─ doTowers(1, B, C, A) │ Базовый: Disk 1 from B to A ├─ Disk 2 from B to C │ Центральный диск └─ doTowers(1, A, B, C) │ Базовый: Disk 1 from A to C

Вывод программы для n=3:

Disk 1 from A to C
Disk 2 from A to B
Disk 1 from C to B
Disk 3 from A to C
Disk 1 from B to A
Disk 2 from B to C
Disk 1 from A to C

Общее число ходов: 2n – 1. Для n=3 — 7 ходов.

Код Ханойских башен с комментариями

public static void doTowers(int topN, char from, char inter, char to) {
    if (topN == 1) {
        // Базовый случай: один диск — просто переносим
        System.out.println("Disk 1 from " + from + " to " + to);
    } else {
        // Шаг 1: переносим (n-1) дисков на вспомогательный стержень
        doTowers(topN - 1, from, to, inter);

        // Шаг 2: переносим оставшийся самый большой диск
        System.out.println("Disk " + topN + " from " + from + " to " + to);

        // Шаг 3: переносим (n-1) дисков со вспомогательного на целевой
        doTowers(topN - 1, inter, from, to);
    }
}

Обход дерева (файловая система)

Классический пример практической рекурсии — подсчёт размера папки со всеми вложенными подпапками.

public static long getFolderSize(File folder) {
    long size = 0;
    for (File file : folder.listFiles()) {
        if (file.isFile()) {
            size += file.length();          // обычный файл
        } else {
            size += getFolderSize(file);    // рекурсивно для подпапки
        }
    }
    return size;
}

Опасности рекурсии и как их избежать

1. StackOverflowError

Глубина стека JVM ограничена (~1–10 тыс. вызовов). Если рекурсия слишком глубокая — стек переполняется.

Решение: замена рекурсии на цикл + явный стек (Stack/Deque).

// Вместо рекурсивного обхода дерева — итеративный
public long getFolderSizeIterative(File root) {
    long size = 0;
    Stack<File> stack = new Stack<>();
    stack.push(root);
    while (!stack.isEmpty()) {
        File current = stack.pop();
        for (File file : current.listFiles()) {
            if (file.isFile()) size += file.length();
            else stack.push(file);
        }
    }
    return size;
}

2. Экспоненциальная сложность

Как в наивном Фибоначчи — одни и те же подзадачи решаются многократно.

Решение: мемоизация (кеширование результатов) или динамическое программирование.

3. Хвостовая рекурсия

Если рекурсивный вызов — последняя операция в методе, это хвостовая рекурсия. JVM не оптимизирует её (в отличие от Kotlin/Scala), поэтому глубокий вызов всё равно приведёт к StackOverflow. Можно использовать Trampoline-паттерн.

Когда применять рекурсию, а когда нет

✅ Рекурсия уместна❌ Лучше цикл
Задача естественно рекурсивна (деревья, графы, комбинаторика)Простая итерация (сумма элементов, поиск максимума)
Глубина рекурсии гарантированно мала (до ~1000)Глубина неизвестна или может быть большой
Алгоритмы «разделяй и властвуй» (Merge Sort, Quick Sort)Критичная к производительности логика на больших данных
Парсинг вложенных структур (JSON, XML)Обычные CRUD-операции

Рекурсивные структуры данных

Некоторые структуры данных определены рекурсивно и естественно обрабатываются рекурсией:

  • Связный список: список — это либо null, либо узел + список (хвост).
  • Бинарное дерево: дерево — это либо null, либо узел + левое поддерево + правое поддерево.
// Рекурсивный подсчёт суммы элементов связного списка
public int sum(ListNode head) {
    if (head == null) return 0;                // базовый случай
    return head.val + sum(head.next);          // рекурсивный случай
}

📝 Итог

Рекурсия — мощный инструмент, когда задача естественно сводится к меньшей копии себя. Обязательно нужен базовый случай. Следи за глубиной: при больших данных — цикл + стек. Для оптимизации используй мемоизацию. Понимание стека вызовов и дерева рекурсии помогает отлаживать и предсказывать поведение программы.
