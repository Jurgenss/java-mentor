🔪 Spring AOP (Aspect-Oriented Programming)

АОП позволяет вынести сквозную функциональность (логирование, транзакции, безопасность) в отдельные модули — аспекты.

Зачем нужен AOP

Проблема: сквозная функциональность (cross-cutting concerns) дублируется в каждом методе.

// Без AOP — логирование в каждом методе
public void transferMoney(Long fromId, Long toId, BigDecimal amount) {
    log.info("Начало перевода: from={}, to={}, amount={}", fromId, toId, amount); // дублируется
    // бизнес-логика
    log.info("Перевод выполнен"); // дублируется
}

public void getBalance(Long accountId) {
    log.info("Запрос баланса: id={}", accountId); // дублируется
    // бизнес-логика
    log.info("Баланс получен"); // дублируется
}

// С AOP — логирование вынесено в аспект
@Aspect
@Component
public class LoggingAspect {
    @Before("execution(* com.example.service.*.*(..))")
    public void logBefore(JoinPoint joinPoint) {
        log.info("Вызов метода: {}", joinPoint.getSignature().getName());
    }
}
// ВСЕ методы сервиса логируются автоматически!
АОП выносит сквозную функциональность (логирование, транзакции, безопасность, кеширование) в отдельные модули — аспекты. Это избавляет от дублирования кода. Spring AOP работает через прокси и применяется к бинам.

Основные понятия AOP

ТерминЧто этоАннотация / Пример
Aspect Модуль со сквозной функциональностью Класс с @Aspect
Advice Действие, выполняемое аспектом @Before, @After, @Around, @AfterReturning, @AfterThrowing
Pointcut Выражение: ГДЕ применять аспект execution(* com.example.service.*.*(..))
Join Point Конкретная точка в программе (метод) Метод transferMoney()
Weaving Процесс внедрения аспекта в код Spring: runtime через прокси

Типы Advice (советов)

АннотацияКогда выполняетсяПример использования
@Before ДО вызова метода Логирование входа в метод, проверка прав
@After ПОСЛЕ метода (даже если исключение) Очистка ресурсов (finally)
@AfterReturning ПОСЛЕ успешного возврата (без исключения) Кеширование результата
@AfterThrowing ПОСЛЕ исключения Логирование ошибок, отправка алертов
@Around ВОКРУГ метода (до и после) Замер времени, транзакции, повторные попытки

Pointcut — выражения (где срабатывает)

// Все public методы во всех классах пакета service
@Before("execution(public * com.example.service.*.*(..))")

// Любой метод с любыми параметрами в классе UserService
@Before("execution(* com.example.service.UserService.*(..))")

// Только метод transferMoney с конкретными параметрами
@Before("execution(* com.example.service.*.transferMoney(Long, Long, BigDecimal))")

// Все методы, помеченные аннотацией @Transactional
@Before("@annotation(org.springframework.transaction.annotation.Transactional)")

// Все методы в классах с аннотацией @RestController
@Before("@within(org.springframework.web.bind.annotation.RestController)")

// Комбинирование (методы сервиса, НО не в пакете internal)
@Before("execution(* com.example.service.*.*(..)) && !execution(* com.example.service.internal.*.*(..))")

// Именованный Pointcut (переиспользование)
@Pointcut("execution(* com.example.service.*.*(..))")
public void serviceLayer() {}

@Before("serviceLayer()")
public void logBefore() { ... }

@After("serviceLayer()")
public void logAfter() { ... }

Полные примеры аспектов

Логирование вызовов:

@Aspect
@Component
public class LoggingAspect {

    @Before("execution(* com.example.service.*.*(..))")
    public void logBefore(JoinPoint joinPoint) {
        String method = joinPoint.getSignature().getName();
        Object[] args = joinPoint.getArgs();
        System.out.println("→ Вызов: " + method + " | аргументы: " + Arrays.toString(args));
    }

    @AfterReturning(pointcut = "execution(* com.example.service.*.*(..))", returning = "result")
    public void logAfter(JoinPoint joinPoint, Object result) {
        System.out.println("← Возврат: " + joinPoint.getSignature().getName() + " | результат: " + result);
    }

    @AfterThrowing(pointcut = "execution(* com.example.service.*.*(..))", throwing = "ex")
    public void logError(JoinPoint joinPoint, Exception ex) {
        System.out.println("✖ Ошибка: " + joinPoint.getSignature().getName() + " | " + ex.getMessage());
    }
}

Замер времени выполнения (@Around):

@Aspect
@Component
public class TimingAspect {

    @Around("execution(* com.example.service.*.*(..))")
    public Object measureTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();

        Object result = joinPoint.proceed(); // выполняем сам метод!

        long time = System.currentTimeMillis() - start;
        System.out.println(joinPoint.getSignature().getName() + " выполнен за " + time + "мс");

        return result;
    }
}

Проверка прав:

@Aspect
@Component
public class SecurityAspect {

    @Before("@annotation(AdminOnly)")
    public void checkAdmin(JoinPoint joinPoint) {
        // Получаем текущего пользователя (например, из SecurityContext)
        User currentUser = SecurityContext.getCurrentUser();
        if (!currentUser.isAdmin()) {
            throw new SecurityException("Доступ запрещён для " + currentUser.getName());
        }
    }
}

// Аннотация-маркер
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface AdminOnly {}

// Использование
@Service
public class UserService {
    @AdminOnly
    public void deleteUser(Long id) { ... } // только админ!
}

Как работает Spring AOP

Spring AOP основан на прокси:

  1. Если класс реализует интерфейс → динамический прокси (JDK Dynamic Proxy)
  2. Если класс без интерфейса → CGLIB прокси (наследует класс)

Ограничения Spring AOP:

  • Работает только с бинами Spring
  • Применяется только к public методам
  • Не срабатывает при вызове метода внутри того же класса (self-invocation)
@Service
public class UserService {

    public void publicMethod() {
        privateMethod(); // вызов изнутри — AOP НЕ сработает!
    }

    @Transactional // не сработает при вызове из publicMethod()!
    private void privateMethod() { ... }
}
Spring AOP работает через прокси (JDK Dynamic Proxy для интерфейсов или CGLIB для классов). Применяется только к public-методам бинов. Self-invocation (вызов метода внутри того же класса) не перехватывается — аспект не сработает.
