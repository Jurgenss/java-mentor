🧪 Тестирование в Java (JUnit + Mockito)

На собесе на джуна обязательно спросят: "Пишете ли вы тесты?" Правильный ответ: "Да, JUnit 5 + Mockito".

Зачем нужны тесты

ПричинаБез тестовС тестами
РегрессияПочинил одно — сломал другое, узнаешь от пользователяТесты упали → сразу видно, что сломалось
РефакторингСтрашно менять кодМеняешь смело — тесты проверят
ДокументацияНепонятно, как метод должен работатьТесты = живая документация
Деплой"Авось прокатит"CI/CD: тесты упали → деплой не прошёл
Тесты — это не "бонус", а обязательная часть разработки. JUnit 5 — фреймворк для модульного тестирования. Mockito — для создания заглушек (моков) зависимостей. Вместе позволяют тестировать логику в изоляции от БД, сети и других сервисов.

Простой пример теста

// Класс, который тестируем
public class Calculator {
    public int sum(int a, int b) { return a + b; }
    public int divide(int a, int b) {
        if (b == 0) throw new IllegalArgumentException("Деление на ноль!");
        return a / b;
    }
}

// Тест
import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {

    private Calculator calc;

    @BeforeEach
    void setUp() {
        calc = new Calculator(); // создаём новый перед каждым тестом
    }

    @Test
    @DisplayName("Сумма двух чисел")
    void testSum() {
        assertEquals(5, calc.sum(2, 3));
        assertEquals(0, calc.sum(-1, 1));
        assertEquals(-5, calc.sum(-2, -3));
    }

    @Test
    @DisplayName("Деление на ноль должно бросать исключение")
    void testDivideByZero() {
        assertThrows(IllegalArgumentException.class,
            () -> calc.divide(10, 0)
        );
    }

    @Test
    @DisplayName("Обычное деление")
    void testDivide() {
        assertEquals(5, calc.divide(10, 2));
    }
}

Mockito — моки и заглушки

Проблема: UserService зависит от UserRepository (БД). Как тестировать UserService без реальной БД?

Решение: Mockito создаёт "заглушку" UserRepository, которой можно управлять.

Три главных метода Mockito:

МетодЧто делает
Mockito.mock(Class)Создать мок-объект
Mockito.when(mock.method()).thenReturn(value)Настроить поведение: "когда вызовут метод — верни value"
Mockito.verify(mock).method()Проверить, что метод БЫЛ вызван

Аннотации Mockito:

АннотацияЧто делает
@MockСоздать мок
@InjectMocksВнедрить моки в тестируемый объект
@ExtendWith(MockitoExtension.class)Включить Mockito в JUnit 5

Полный пример с Mockito

// Сервис, который тестируем
@Service
public class UserService {
    @Autowired
    private UserRepository repo;

    public User findById(Long id) {
        return repo.findById(id)
            .orElseThrow(() -> new UserNotFoundException(id));
    }

    public User create(String name) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("Имя обязательно");
        }
        return repo.save(new User(name));
    }
}

// Тест с Mockito
@ExtendWith(MockitoExtension.class)
class UserServiceTest {

    @Mock
    private UserRepository repo; // мок — не настоящая БД!

    @InjectMocks
    private UserService service; // сюда внедрятся моки

    @Test
    @DisplayName("Найти пользователя по ID — успешно")
    void testFindById_Success() {
        // Given (дано): настраиваем мок
        User expected = new User(1L, "Иван");
        when(repo.findById(1L)).thenReturn(Optional.of(expected));

        // When (когда): вызываем метод
        User actual = service.findById(1L);

        // Then (тогда): проверяем результат
        assertEquals("Иван", actual.getName());
        verify(repo).findById(1L); // убеждаемся, что repo.findById БЫЛ вызван
    }

    @Test
    @DisplayName("Найти пользователя — не найден → исключение")
    void testFindById_NotFound() {
        when(repo.findById(999L)).thenReturn(Optional.empty());

        assertThrows(UserNotFoundException.class,
            () -> service.findById(999L)
        );
    }

    @Test
    @DisplayName("Создать пользователя — пустое имя → ошибка")
    void testCreate_EmptyName() {
        assertThrows(IllegalArgumentException.class,
            () -> service.create("")
        );
        verify(repo, never()).save(any()); // repo.save НЕ вызывался
    }
}

Паттерн Given-When-Then (AAA)

ФазаЧто делаемMockito
Given (Arrange)Подготавливаем данные, настраиваем мокиwhen(...).thenReturn(...)
When (Act)Вызываем тестируемый методСам вызов метода
Then (Assert)Проверяем результатassertEquals, verify(...)

Интеграционные тесты (Spring Boot)

@SpringBootTest
@AutoConfigureMockMvc
class UserControllerIntegrationTest {

    @Autowired
    private MockMvc mockMvc; // эмулирует HTTP-запросы без реального сервера

    @Test
    void testGetAllUsers() throws Exception {
        mockMvc.perform(get("/api/users"))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$[0].name").value("Иван"));
    }

    @Test
    void testCreateUser() throws Exception {
        mockMvc.perform(post("/api/users")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"name\": \"Пётр\", \"email\": \"peter@mail.ru\"}"))
            .andExpect(status().isCreated());
    }
}

Пирамида тестов

       /\
      /  \       E2E (end-to-end) — мало, самые медленные
     /    \
    /──────\    Интеграционные — среднее количество
   /        \
  /──────────\  Unit-тесты — много, самые быстрые
  • Unit-тесты (70%) — тестируют один класс в изоляции (JUnit + Mockito)
  • Интеграционные (20%) — тестируют взаимодействие с БД, сетью (@SpringBootTest)
  • E2E (10%) — тестируют всё приложение целиком (Selenium, Testcontainers)
