📌 static и final в Java

Два ключевых слова, которые кардинально меняют поведение переменных, методов и классов. Спрашивают на каждом собесе.

static — принадлежит классу, а не объекту

Статическое поле или метод едино для всех экземпляров. Хранится в памяти один раз и загружается при первом обращении к классу.

static-поле

public class User {
    private String name;           // у каждого свой
    public static int count = 0;   // общее для всех!

    public User(String name) {
        this.name = name;
        count++; // увеличиваем общий счётчик
    }
}

User u1 = new User("Иван");
System.out.println(User.count); // 1
User u2 = new User("Мария");
System.out.println(User.count); // 2 — общее!

static-метод

Вызывается без создания объекта. Не имеет доступа к this и нестатическим полям.

public class MathUtils {
    public static int sum(int a, int b) {
        return a + b; // не нужен объект
    }
}

int result = MathUtils.sum(5, 3); // вызов через класс, не через объект

static-блок

Выполняется один раз при загрузке класса. Для сложной инициализации статических полей.

public class Config {
    public static String appName;

    static {
        // сложная логика загрузки конфига
        appName = "MyApp v" + loadVersion();
        System.out.println("Класс Config загружен!");
    }

    private static String loadVersion() {
        return "2.0";
    }
}

static import (Java 5+)

Импорт статических методов/констант, чтобы использовать без имени класса.

import static java.lang.Math.PI;
import static java.lang.Math.sqrt;

double x = PI;          // вместо Math.PI
double y = sqrt(16);    // вместо Math.sqrt(16)
static означает принадлежность классу, а не экземпляру. Статические поля — общие для всех объектов. Статические методы вызываются без создания объекта. Статические блоки выполняются один раз при загрузке класса.

final — "нельзя изменить"

Значение зависит от того, на что повесили final.

final на...ЗапрещаетПример
Примитивной переменной Менять значение final int x = 10; // x = 20; ❌
Ссылочной переменной Переназначать ссылку (но объект можно менять!) final List<String> list = new ArrayList<>(); list.add("A"); // ✅ list = new ArrayList<>(); // ❌
Методе Переопределять в наследниках public final void doIt() { }
Классе Наследовать public final class String { }
Параметре метода Менять внутри метода void calc(final int x) { // x = 5; ❌ }

final + ссылка — важный нюанс!

final List<String> names = new ArrayList<>();
names.add("Иван");   // ✅ объект менять можно
names.add("Мария");  // ✅
// names = new ArrayList<>(); // ❌ ссылку переназначить нельзя

final-метод

public class Parent {
    public final void cannotOverride() {
        System.out.println("Не переопределишь!");
    }
}

public class Child extends Parent {
    // @Override
    // public void cannotOverride() { } // ❌ Ошибка! final-метод
}

final-класс

public final class String { } // нельзя наследовать

// public class MyString extends String { } // ❌ Ошибка!
final запрещает изменение: для примитива — значения, для ссылки — переподвязку (но объект менять можно), для метода — переопределение, для класса — наследование. static final вместе — константа класса.

static final — константа

Неизменяемое значение, общее для всех. Именование: UPPER_SNAKE_CASE.

public class Constants {
    public static final int MAX_USERS = 100;
    public static final String APP_NAME = "MyApp";
    public static final double PI = 3.14159;
}

// Использование:
if (count > Constants.MAX_USERS) { ... }

Порядок инициализации в классе

Важно понимать, что когда выполняется.

public class InitDemo {
    static { System.out.println("1. Статический блок"); }
    static String staticField = initStatic();

    { System.out.println("3. Нестатический блок"); }
    String field = initField();

    public InitDemo() {
        System.out.println("4. Конструктор");
    }

    static String initStatic() {
        System.out.println("2. Статическое поле");
        return "static";
    }

    String initField() {
        System.out.println("3.1. Нестатическое поле");
        return "field";
    }
}

// При первом new InitDemo() вывод:
// 1. Статический блок
// 2. Статическое поле
// 3. Нестатический блок
// 3.1. Нестатическое поле
// 4. Конструктор

// При втором new InitDemo() вывод:
// 3. Нестатический блок       (статическое — только раз!)
// 3.1. Нестатическое поле
// 4. Конструктор
КогдаЧто выполняется
При загрузке класса (1 раз)Статические поля и блоки в порядке объявления
При создании объекта (каждый раз)Нестатические поля и блоки → Конструктор

Сокрытие статических методов (hiding)

Статические методы не переопределяются — они скрываются. Нет полиморфизма!

class Parent {
    static void print() { System.out.println("Parent"); }
}

class Child extends Parent {
    static void print() { System.out.println("Child"); } // hiding!
}

Parent p = new Child();
p.print(); // "Parent" — вызывается по типу ссылки, не объекта!
Статические методы не переопределяются, а скрываются (hiding). Вызов идёт по типу ссылки, а не по реальному типу объекта. Это не полиморфизм! Parent p = new Child(); p.staticMethod(); вызовет метод Parent.
