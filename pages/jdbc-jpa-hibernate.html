Уровень 1: Чистый JDBC

Connection conn = null;
PreparedStatement stmt = null;
ResultSet rs = null;
try {
    conn = DriverManager.getConnection(url, user, pass);
    conn.setAutoCommit(false);

    stmt = conn.prepareStatement("UPDATE accounts SET balance = balance - ? WHERE id = ?");
    stmt.setDouble(1, 500.00);
    stmt.setInt(2, 1);
    stmt.executeUpdate();

    conn.commit();
} catch (SQLException e) {
    if (conn != null) conn.rollback();
} finally {
    if (rs != null) try { rs.close(); } catch (SQLException e) {}
    if (stmt != null) try { stmt.close(); } catch (SQLException e) {}
    if (conn != null) try { conn.close(); } catch (SQLException e) {}
}

Минимум 30 строк на один простой UPDATE. 80% кода — boilerplate.

Уровень 2: JdbcTemplate (Spring)

@Repository
public class AccountRepository {
    @Autowired
    private JdbcTemplate jdbc;

    public BigDecimal getBalance(Long id) {
        return jdbc.queryForObject(
            "SELECT balance FROM accounts WHERE id = ?",
            BigDecimal.class, id
        );
    }

    public void withdraw(Long id, BigDecimal amount) {
        jdbc.update(
            "UPDATE accounts SET balance = balance - ? WHERE id = ?",
            amount, id
        );
    }
}

@Service
@Transactional
public class TransferService {
    @Autowired
    private AccountRepository repo;

    public void transfer(Long from, Long to, BigDecimal amount) {
        if (repo.getBalance(from).compareTo(amount) < 0) {
            throw new RuntimeException("Недостаточно средств!");
        }
        repo.withdraw(from, amount);
        repo.deposit(to, amount);
    }
}

SQL всё ещё пишем, но boilerplate исчез. Транзакции — одна аннотация.

Уровень 3: JPA + Hibernate

@Entity
@Table(name = "accounts")
public class Account {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;
    private BigDecimal balance;
    // геттеры/сеттеры...
}

@Repository
public class AccountRepository {
    @PersistenceContext
    private EntityManager em;

    public Account findById(Long id) {
        return em.find(Account.class, id);
    }
    // save() НЕ НУЖЕН — Hibernate отслеживает изменения!
}

@Service
@Transactional
public class TransferService {
    @Autowired
    private AccountRepository repo;

    public void transfer(Long fromId, Long toId, BigDecimal amount) {
        Account from = repo.findById(fromId);
        Account to = repo.findById(toId);

        if (from.getBalance().compareTo(amount) < 0) {
            throw new RuntimeException("Недостаточно средств!");
        }

        from.setBalance(from.getBalance().subtract(amount));
        to.setBalance(to.getBalance().add(amount));
        // Hibernate сам сгенерирует UPDATE при выходе из @Transactional!
    }
}

Ни одного SQL-запроса. Hibernate сам отслеживает изменения объектов (dirty checking) и генерирует SQL.

JPA vs Hibernate — в чём разница

JPAHibernate
Что этоСпецификация (набор правил, интерфейсов)Реализация (конкретный код)
АналогияГОСТ на розеткиКонкретная розетка
Пакетjavax.persistence.*org.hibernate.*
JPA — это спецификация (интерфейсы), Hibernate — её реализация. В коде мы используем JPA-аннотации (@Entity, @Table, @Id), а под капотом Hibernate генерирует SQL. Если завтра появится другая реализация JPA — код не изменится.

Как Hibernate работает под капотом

Dirty Checking (отслеживание изменений):

  1. При загрузке объекта Hibernate сохраняет "снимок" (snapshot) его состояния
  2. При коммите транзакции сравнивает текущее состояние со снимком
  3. Если есть изменения — генерирует UPDATE только для изменённых колонок

Кеш первого уровня (L1):

  • В рамках одной сессии (транзакции)
  • Повторный запрос того же объекта — из кеша, без SQL
  • Всегда включён, нельзя отключить

Кеш второго уровня (L2):

  • Между сессиями, на уровне SessionFactory
  • Подключается отдельно (EhCache, Hazelcast)
  • Хранит объекты в памяти между транзакциями
@Entity
@Cacheable
@org.hibernate.annotations.Cache(usage = CacheConcurrencyStrategy.READ_WRITE)
public class Account { ... }

Уровень 4: Spring Data JPA (совсем без кода)

// Только интерфейс — реализацию создаст Spring!
@Repository
public interface AccountRepository extends JpaRepository<Account, Long> {
    
    // Spring сам напишет реализацию по имени метода!
    List<Account> findByBalanceGreaterThan(BigDecimal amount);
    
    Optional<Account> findByName(String name);
    
    @Query("SELECT a FROM Account a WHERE a.balance > :min")
    List<Account> findRichAccounts(@Param("min") BigDecimal min);
    
    @Query(value = "SELECT * FROM accounts WHERE name LIKE %:name%", nativeQuery = true)
    List<Account> searchByName(@Param("name") String name);
}

// Использование:
@Service
@Transactional
public class AccountService {
    @Autowired
    private AccountRepository repo;
    
    public List<Account> getRichAccounts() {
        return repo.findByBalanceGreaterThan(new BigDecimal("10000"));
    }
}

Spring Data JPA генерирует SQL по имени метода: findByBalanceGreaterThan → WHERE balance > ?.

Когда что использовать в реальном проекте

ЗадачаИнструментПочему
Простые CRUD-операцииSpring Data JPAПишем только интерфейс
Сложный SELECT с JOINJPQL / Native QueryКонтроль над запросом
Массовая вставкаJDBC batch / JdbcTemplateМаксимальная скорость
Отчёты, аналитикаJdbcTemplate + Native SQLСложные агрегации
Горячие данныеHibernate L2 cache + RedisБез запросов в БД
В реальных проектах используют гибридный подход: Spring Data JPA для 80% стандартных операций (CRUD), JdbcTemplate или нативные запросы для сложных отчётов и массовых операций. Плюс кеширование (Hibernate L2, Redis) для горячих данных.
