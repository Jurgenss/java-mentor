⚠ Исключения в Java

Исключения — это способ обработки ошибок. На собесе спросят иерархию, checked/unchecked и try-with-resources.

Иерархия исключений

Throwable
 ├── Error (критические ошибки JVM — НЕ обрабатываем)
 │    ├── StackOverflowError
 │    ├── OutOfMemoryError
 │    └── VirtualMachineError
 │
 └── Exception (можно и нужно обрабатывать)
      ├── RuntimeException (unchecked — необязательно)
      │    ├── NullPointerException
      │    ├── ArrayIndexOutOfBoundsException
      │    ├── ArithmeticException (/ by zero)
      │    ├── IllegalArgumentException
      │    ├── ClassCastException
      │    └── NumberFormatException
      │
      └── IOException (checked — обязательно!)
           ├── FileNotFoundException
           └── EOFException
Throwable — корень иерархии. Error — критические ошибки JVM, их не обрабатываем. Exception — делятся на checked (компилятор требует обработки) и unchecked / RuntimeException (опционально).

Checked vs Unchecked

CheckedUnchecked (RuntimeException)
Проверка✅ Компилятор заставляет обработать❌ Необязательно
Наследованиеextends Exceptionextends RuntimeException
ПримерыIOException, SQLException, FileNotFoundExceptionNullPointerException, ArithmeticException, IllegalArgumentException
ПриродаВнешние факторы (файл не найден, сеть упала)Ошибки программиста (забыл проверить на null)
Обработкаtry-catch или throws в сигнатуреПо желанию
Checked-исключения — компилятор заставляет их обработать (try-catch или throws). Это внешние ошибки: файл не найден, сеть недоступна. Unchecked (RuntimeException) — ошибки программиста: NullPointerException, выход за границы массива. Их обрабатывать необязательно.

throw vs throws

Что делаетБросает исключениеПредупреждает об исключении
Где пишетсяВнутри методаВ сигнатуре метода
Работает сОбъектом исключенияКлассом исключения

// throw — бросаем объект исключения
public void setAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("Возраст не может быть отрицательным!");
    }
    this.age = age;
}

// throws — предупреждаем в сигнатуре
public void readFile(String path) throws IOException {
    FileReader reader = new FileReader(path); // может бросить IOException
    // ...
}

Запоминалка: throw — глагол (бросаю), throws — предупреждение на двери (осторожно, исключение!).

try-catch-finally

try {
    // код, который может бросить исключение
    int result = 10 / 0;
} catch (ArithmeticException e) {
    // обработка конкретного исключения
    System.out.println("Деление на ноль: " + e.getMessage());
} catch (Exception e) {
    // обработка любого другого исключения (порядок важен — от частного к общему!)
    System.out.println("Что-то пошло не так: " + e.getMessage());
} finally {
    // выполняется ВСЕГДА — даже если был return или исключение
    System.out.println("Блок finally");
}

Правила:

  • catch — порядок от частного к общему (иначе ошибка компиляции)
  • finally — выполняется всегда, даже если был return
  • Можно try-finally без catch
  • Можно несколько catch на один try
  • С Java 7 можно ловить несколько в одном catch: catch (IOException | SQLException e)

finally и return — ловушка!

// finally перебивает return!
static int test() {
    try {
        return 1;
    } finally {
        return 2; // ПЕРЕБИВАЕТ return 1!
    }
}
System.out.println(test()); // 2

// Никогда не пиши return в finally!

try-with-resources (Java 7+)

Автоматическое закрытие ресурсов, реализующих AutoCloseable.

// Было (Java 6):
BufferedReader reader = null;
try {
    reader = new BufferedReader(new FileReader("file.txt"));
    String line = reader.readLine();
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (reader != null) {
        try {
            reader.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

// Стало (Java 7+):
try (BufferedReader reader = new BufferedReader(new FileReader("file.txt"))) {
    String line = reader.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
// reader.close() вызовется автоматически!

Несколько ресурсов:

try (Connection conn = DriverManager.getConnection(url);
     PreparedStatement stmt = conn.prepareStatement(sql);
     ResultSet rs = stmt.executeQuery()) {

    while (rs.next()) { ... }

} catch (SQLException e) {
    e.printStackTrace();
}
// Закроются в обратном порядке: rs → stmt → conn

Создание своих исключений

// Checked — extends Exception
public class InsufficientFundsException extends Exception {
    public InsufficientFundsException(String message) {
        super(message);
    }
}

// Unchecked — extends RuntimeException
public class UserNotFoundException extends RuntimeException {
    public UserNotFoundException(String message) {
        super(message);
    }

    public UserNotFoundException(String message, Throwable cause) {
        super(message, cause); // цепочка исключений
    }
}

Цепочка исключений (chaining)

try {
    // ...
} catch (SQLException e) {
    // Оборачиваем checked в unchecked с сохранением причины
    throw new RuntimeException("Ошибка базы данных", e);
}

// Позже можно достать причину:
catch (RuntimeException e) {
    Throwable cause = e.getCause(); // оригинальный SQLException
}
