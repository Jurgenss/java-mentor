🐳 Docker для Java-разработчика

Docker — это способ упаковать приложение со всеми зависимостями в контейнер. На джуна спросят: зачем нужен Docker, основные команды, Dockerfile, docker-compose.

Зачем нужен Docker

Проблема: "На моей машине работает, а на сервере — нет". Разные версии Java, разные ОС, разные настройки.

Решение: Docker упаковывает приложение + все зависимости (JDK, библиотеки, настройки) в единый образ. Этот образ запускается одинаково везде: на твоём ноутбуке, на сервере, в облаке.

Без DockerС Docker
Установи JDK 17Образ уже содержит JDK 17
Установи PostgreSQLКонтейнер с PostgreSQL за 1 команду
Настрой переменные окруженияПрописаны в Dockerfile/compose
"У меня не запускается""docker compose up" — и всё работает
Docker — это платформа для контейнеризации. Контейнер — изолированная среда с приложением и всеми зависимостями. В отличие от виртуальной машины, контейнеры используют ядро хостовой ОС и занимают меньше ресурсов. Образ (image) — шаблон, контейнер (container) — запущенный экземпляр образа.

Dockerfile для Spring Boot

Dockerfile — текстовый файл с инструкциями для сборки образа.

# Этап 1: сборка приложения
FROM eclipse-temurin:17-jdk AS builder
WORKDIR /app
COPY pom.xml .
COPY src ./src
RUN ./mvnw package -DskipTests

# Этап 2: финальный образ (только JAR)
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=builder /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

Инструкции Dockerfile:

ИнструкцияЧто делает
FROM imageБазовый образ (стартовая точка)
WORKDIR /pathРабочая директория внутри контейнера
COPY src dstСкопировать файлы с хоста в контейнер
RUN commandВыполнить команду при сборке образа
EXPOSE portОбъявить порт (документирование)
ENTRYPOINT [...]Команда при запуске контейнера
ENV VAR=valueЗадать переменную окружения

Multi-stage build — два этапа

Зачем: на первом этапе собираем JAR (нужен JDK + Maven), на втором — только JRE + JAR. Итоговый образ в 5 раз меньше.

# Этап 1: сборка (JDK + Maven) — ~500 MB
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /app
COPY . .
RUN mvn package -DskipTests

# Этап 2: запуск (только JRE) — ~100 MB
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=builder /app/target/*.jar app.jar
ENTRYPOINT ["java", "-jar", "app.jar"]

Docker Compose — запуск нескольких сервисов

docker-compose.yml описывает все сервисы приложения. Одна команда docker compose up — и запущены БД, приложение, Redis, Kafka.

version: '3.8'

services:
  # PostgreSQL
  postgres:
    image: postgres:17
    environment:
      POSTGRES_DB: bank
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: secret
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

  # Spring Boot приложение
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/bank
      SPRING_DATASOURCE_USERNAME: postgres
      SPRING_DATASOURCE_PASSWORD: secret
    depends_on:
      - postgres

  # Redis для кеша
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:

Запуск:

docker compose up -d      # запустить всё в фоне
docker compose ps         # статус сервисов
docker compose logs -f app # логи приложения
docker compose down       # остановить и удалить всё

Docker для базы данных (без установки)

Одна команда — и PostgreSQL готов к работе, не нужно ничего устанавливать:

docker run -d \
  --name my-postgres \
  -e POSTGRES_DB=bank \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=secret \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql/data \
  postgres:17

После этого в Java: jdbc:postgresql://localhost:5432/bank — работает!

Практический пример: Spring Boot + PostgreSQL в Docker

Структура проекта:

# 1. Клонировал проект
git clone https://github.com/user/myapp.git
cd myapp

# 2. Запустил
docker compose up -d

# 3. Всё работает:
# - PostgreSQL на порту 5432
# - Приложение на порту 8080
# - Таблицы созданы (если ddl-auto=update)
# НЕ НУЖНО устанавливать ни Java, ни Maven, ни PostgreSQL!
