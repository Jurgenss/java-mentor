📋 Логирование (SLF4J + Logback)

Логирование — это запись информации о работе приложения. На собесе спросят: какие уровни логирования, какой фреймворк используешь, как настроить.

Зачем нужно логирование:

  • 🔍 Отладка — найти ошибку в проде, когда дебаггер не подключить
  • 📊 Мониторинг — что происходит с приложением
  • 📝 Аудит — кто и когда менял данные

SLF4J — фасад, Logback — реализация:

// SLF4J — интерфейс (фасад)
// Logback / Log4j2 — реализация (можно менять без изменения кода)

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class UserService {
    private static final Logger log = LoggerFactory.getLogger(UserService.class);

    public void createUser(String name) {
        log.info("Создаём пользователя: {}", name); // {} — плейсхолдер
        // ...
        log.debug("Пользователь создан успешно");
    }
}

Уровни логирования (от важного к неважному):

УровеньКогда использоватьПример
ERRORОшибка, требует вмешательстваБД недоступна, не прошла оплата
WARNПотенциальная проблемаРетрай запроса, близок лимит
INFOВажные события (дефолт в проде)Пользователь зарегистрирован, заказ создан
DEBUGИнформация для отладкиЗначения переменных, шаги алгоритма
TRACEМаксимальная детализацияКаждый вход/выход из метода

Почему не System.out.println?

  • ❌ Нельзя управлять уровнем (либо пишем, либо нет)
  • ❌ Нельзя настроить формат (дата, поток, класс)
  • ❌ Нельзя писать в файл/БД/сеть
  • ❌ Медленно (синхронный вывод в консоль)

Плейсхолдеры {} — почему лучше конкатенации:

// ❌ Плохо — конкатенация выполняется ВСЕГДА, даже если DEBUG выключен
log.debug("Пользователь: " + user.getName() + ", возраст: " + user.getAge());

// ✅ Хорошо — если DEBUG выключен, строка НЕ собирается (быстрее)
log.debug("Пользователь: {}, возраст: {}", user.getName(), user.getAge());

Настройка в Spring Boot (application.properties):

# Уровень для всего приложения
logging.level.root=INFO

# Уровень для конкретного пакета
logging.level.com.example.service=DEBUG

# Запись в файл
logging.file.name=logs/myapp.log

# Формат
logging.pattern.console=%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n

@Slf4j (Lombok) — ещё короче:

@Slf4j
@Service
public class UserService {
    public void createUser(String name) {
        log.info("Создаём пользователя: {}", name); // log генерируется автоматически!
    }
}
Для логирования использую SLF4J с Logback (стандарт в Spring Boot). Уровни: ERROR, WARN, INFO, DEBUG, TRACE. В проде обычно INFO, для отладки переключаю на DEBUG. Плейсхолдеры {} вместо конкатенации строк — экономят ресурсы. Lombok @Slf4j генерирует логгер автоматически.

📦 Maven

Maven — система сборки. Управляет зависимостями, компилирует, запускает тесты, собирает JAR/WAR.

Основные команды:

КомандаЧто делает
mvn cleanУдалить папку target (все собранные файлы)
mvn compileСкомпилировать .java → .class
mvn testЗапустить тесты
mvn packageСобрать JAR/WAR (включает compile + test)
mvn installpackage + установить в локальный репозиторий (~/.m2)
mvn clean installПолная пересборка с нуля
mvn spring-boot:runЗапустить Spring Boot приложение

Жизненный цикл Maven (фазы):

clean → validate → compile → test → package → verify → install → deploy

pom.xml — основные секции:

<dependencies>
    <dependency>                          
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
        <scope>compile</scope>            
    </dependency>

    <dependency>
        <groupId>org.postgresql</groupId>
        <artifactId>postgresql</artifactId>
        <scope>runtime</scope>            
    </dependency>

    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <scope>provided</scope>           
    </dependency>
</dependencies>

Scope зависимостей:

ScopeКогда доступнаПример
compileВсегда (по умолчанию)Spring, Hibernate
runtimeВ рантайме, не при компиляцииJDBC-драйвер
providedКомпиляция + тесты, НЕ в JARLombok, Servlet API
testТолько при тестированииJUnit, Mockito

🐘 Gradle (кратко)

Gradle — более современная альтернатива Maven. Конфигурация на Groovy или Kotlin DSL.

build.gradle (Groovy):

plugins {
    id 'java'
    id 'org.springframework.boot' version '3.2.0'
}

group = 'com.example'
version = '1.0.0'

repositories {
    mavenCentral()
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    runtimeOnly 'org.postgresql:postgresql'
    compileOnly 'org.projectlombok:lombok'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

Maven vs Gradle:

MavenGradle
КонфигурацияXML (pom.xml)Groovy/Kotlin DSL
СкоростьМедленнееБыстрее (инкрементальная сборка, кеш)
ГибкостьЖёсткий жизненный циклМожно кастомизировать
КогдаБольшинство старых проектовНовые проекты, Android
