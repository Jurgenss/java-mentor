🧠 Память JVM: Stack и Heap

На собесе спросят: где хранятся переменные, что такое стек и куча, чем отличаются, что такое GC.

Структура памяти JVM

┌─────────────────────────────────────┐
│           JVM Memory                │
├─────────────────────────────────────┤
│  Stack (для каждого потока свой)    │ ← локальные переменные, примитивы, ссылки
├─────────────────────────────────────┤
│  Heap (общая для всех)              │ ← объекты, массивы, строки
│  ├── Young Generation               │
│  │   ├── Eden                       │
│  │   └── Survivor (S0, S1)          │
│  └── Old Generation (Tenured)       │
├─────────────────────────────────────┤
│  Metaspace (Java 8+)                │ ← метаданные классов, статика
├─────────────────────────────────────┤
│  PC Register, Native Stack          │ ← счётчик команд, нативные вызовы
└─────────────────────────────────────┘

Stack vs Heap

StackHeap
Что хранитсяЛокальные переменные, примитивы, ссылкиОбъекты, массивы
РазмерМаленький (обычно 512KB - 1MB на поток)Большой (до GB)
Скорость⚡ Очень быстрая🐢 Медленнее
ОбластьДля каждого потока свояОбщая для всех потоков
ОчисткаАвтоматически при выходе из методаGarbage Collector
ОшибкиStackOverflowErrorOutOfMemoryError
Stack — область памяти для локальных переменных и ссылок, у каждого потока своя. Быстрая, очищается автоматически при выходе из метода. Heap — общая область для объектов, очищается Garbage Collector. Ссылки хранятся в Stack, а сами объекты — в Heap.

Пример: где что лежит

public void example() {
    int x = 10;                    // примитив x → в Stack
    String s = "Hello";            // ссылка s → в Stack, объект "Hello" → в Heap (String Pool)
    User user = new User("Иван");  // ссылка user → в Stack, объект User → в Heap
}
STACK                          HEAP
┌──────────────┐               ┌──────────────────┐
│ x = 10       │               │ "Hello" (pool)   │
│ s  ──────────┼──────────────>│                  │
│ user ────────┼──┐            │ User{name="Иван"}│
└──────────────┘  └───────────>│                  │
                               └──────────────────┘

Стек вызовов методов

main() → methodA() → methodB()

STACK (растёт вниз):
┌─────────────────┐
│ main: args      │
│ methodA: x=5    │
│ methodB: y=10   │ ← текущий фрейм (вершина)
└─────────────────┘
Каждый вызов создаёт фрейм. Возврат — фрейм удаляется (LIFO).

Heap: Young vs Old Generation

Heap делится на два поколения — это оптимизация для GC.

Young Generation (маленькая, частая очистка)
├── Eden — новые объекты
├── Survivor S0
└── Survivor S1

Old (Tenured) Generation (большая, редкая очистка)
└── объекты, пережившие несколько сборок

Как работает сборка мусора (упрощённо):

  1. Новые объекты → Eden
  2. Eden заполнился → Minor GC: живые объекты → Survivor S0
  3. Ещё раз заполнился → живые → S1 (старые → Old Gen)
  4. Old Gen заполнился → Major GC (Full GC): медленный, останавливает мир (Stop-the-World)

Garbage Collector — как определить мусор

GC удаляет объекты, на которые нет ссылок из Stack или других живых объектов.

// Объект становится мусором, когда ссылка на него потеряна
User user = new User("Иван");
user = null;   // объект User теперь недостижим → GC удалит

Типы GC в Java:

GCОсобенности
Serial GCОднопоточный, для маленьких приложений
Parallel GCМногопоточный, дефолт в Java 8
G1 GCДефолт в Java 9+, баланс скорость/паузы

Что такое Metaspace

До Java 8 была область PermGen (фиксированный размер). С Java 8+ — Metaspace (растёт динамически).

  • Хранит метаданные классов, методов, статические поля
  • Не участвует в обычном GC (только при выгрузке классов)

Пример утечки:

// Плохо — статическая коллекция никогда не очищается
public class Cache {
    private static List<Object> list = new ArrayList<>();
    public static void add(Object o) { list.add(o); } // GC не соберёт!
}

// Хорошо — WeakReference или ограниченный размер
private static Map<Key, Value> cache = new WeakHashMap<>();

Флаги JVM для памяти

java -Xms512m -Xmx2g -Xss1m MyApp

-Xms512m  — начальный размер heap (start)
-Xmx2g    — максимальный размер heap
-Xss1m    — размер стека одного потока
-XX:+UseG1GC — использовать G1 GC
