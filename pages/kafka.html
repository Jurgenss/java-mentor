📨 Apache Kafka

Kafka — распределённый брокер сообщений. Используется для асинхронного общения между сервисами, потоковой обработки данных, event-driven архитектуры.

Что такое Kafka и зачем она нужна

Проблема: сервис A должен оповестить сервисы B, C, D о событии. Если вызывать их по HTTP — A ждёт ответа от всех. Если B упал — событие потеряется.

Решение: Kafka — посредник. A отправляет сообщение в Kafka, и сразу свободен. B, C, D читают из Kafka в своём темпе. Если кто-то упал — сообщение не потеряется, обработает позже.

Apache Kafka — это распределённый брокер сообщений и платформа для потоковой обработки данных. Гарантирует сохранность сообщений на диске, позволяет перечитывать старые сообщения и масштабируется горизонтально.

Основные понятия

ТерминАналогияЧто делает
ProducerПочтальон, отправляющий письмоОтправляет сообщения в топик
ConsumerЧеловек, проверяющий почтовый ящикЧитает сообщения из топика
Topic (топик)Почтовый ящик / папкаКатегория, куда пишут и откуда читают
PartitionОтделение в ящикеЧасть топика для параллельной обработки
BrokerПочтовое отделениеСервер Kafka (их обычно несколько)
Consumer GroupГруппа людей, разбирающих почтуПотребители, делящие нагрузку
OffsetЗакладка в книгеПозиция, до которой прочитали сообщения
Producer → Kafka Broker → Topic "orders"
                              ├── Partition 0: [msg1, msg2, msg3...]
                              ├── Partition 1: [msg4, msg5, msg6...]
                              └── Partition 2: [msg7, msg8, msg9...]
                                   ↓
                              Consumer Group "order-processors"
                              ├── Consumer 1 читает Partition 0
                              ├── Consumer 2 читает Partition 1
                              └── Consumer 3 читает Partition 2

Гарантии доставки

УровеньОписание
At most onceСообщение может потеряться, но не дублируется
At least onceСообщение точно дойдёт, но может дублироваться (по умолчанию)
Exactly onceСообщение дойдёт ровно один раз (идемпотентный producer + транзакции)

Spring Boot + Kafka

Зависимость:

<dependency>
    <groupId>org.springframework.kafka</groupId>
    <artifactId>spring-kafka</artifactId>
</dependency>

Конфигурация (application.properties):

spring.kafka.bootstrap-servers=localhost:9092
spring.kafka.consumer.group-id=order-processors
spring.kafka.consumer.auto-offset-reset=earliest

Producer (отправка сообщений):

@Service
public class OrderProducer {

    @Autowired
    private KafkaTemplate<String, OrderEvent> kafka;

    public void sendOrderCreated(Order order) {
        OrderEvent event = new OrderEvent(order.getId(), order.getUserId());
        kafka.send("order-created", event);
        // Всё! Сообщение ушло, метод сразу завершился
    }
}

Consumer (чтение сообщений):

@Service
public class OrderConsumer {

    @KafkaListener(topics = "order-created", groupId = "email-service")
    public void handleOrderCreated(OrderEvent event) {
        // Отправляем email пользователю
        emailService.sendOrderConfirmation(event.getUserId());
        // Если упадёт — Kafka повторит (at least once)
    }
}

СкоростьМиллионы сообщений/секДесятки тысяч/сек
МасштабированиеГоризонтальное (partitions)Сложнее
МаршрутизацияПростая (топики)Сложная (exchanges, bindings)
КогдаПотоковая обработка, event sourcing, логиRPC, фоновые задачи, уведомления

Kafka в Docker

docker-compose.yml:

version: '3.8'
services:
  zookeeper:
    image: confluentinc/cp-zookeeper:7.5.0
    environment:
      ZOOKEEPER_CLIENT_PORT: 2181

  kafka:
    image: confluentinc/cp-kafka:7.5.0
    ports:
      - "9092:9092"
    environment:
      KAFKA_BROKER_ID: 1
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
    depends_on:
      - zookeeper
